# 요구사항

## 목표와 용어

**쉬운 UX + 내 관심사와 맞는 이슈 선택 = 2030의 정치 관심도 제고.**

보고서의 핵심 가치는 사용자가 관심을 표시한 이슈들의 공통 쟁점과 차이를 이해하는 것이다. 관심 분류 비율은 보조 정보다. 사용자의 정치적 좌우 성향을 추론하는 기능은 범위에 넣지 않는다.

| 용어 | 의미 |
| --- | --- |
| 기사 | 언론사에서 발행한 보도. articles에 제목·description·URL 등의 메타데이터 저장 |
| 이슈 | 구체적인 사건·발표·전개. 여러 근거 기사로 내용 구성 |
| 상세 | 우리 서비스가 구성한 요약·관점·용어 설명. 원문 기사와 구분 |
| 분류 | 주거·경제 등 관심 영역. issue_categories의 값이며 이슈와 다름 |
| 후속 | 이전 이슈와 연관된 새로운 사실·전개. 별도 이슈로 관리 |

## 기능과 유즈케이스

| ID | 기능 | 기본 흐름 | 수용 기준 |
| --- | --- | --- | --- |
| AUTH-01 | 카카오 로그인 | 카카오 식별 확인 → 사용자 조회/생성 → 서비스 세션 발급 | kakao_id 중복 사용자 없음. 이메일만으로 계정 병합하지 않음 |
| AUTH-02 | 세션 갱신·종료 | refresh 검증 → 기존 토큰 소비 → 새 토큰 발급 | 원문 토큰 저장 금지. 소비·갱신 원자 처리. 만료·폐기 토큰 거절 |
| ONB-01 | 관심사 설정 | 대표 분류·대상 선택 → 선호 행 반영 → 온보딩 완료 | 같은 사용자·분류/대상 중복 행 없음. 건너뛰기 구분 |
| FEED-01 | 이슈 카드 피드 | 공개 이슈 → 추천 순서 → 카드 요약 제공 | 비공개 이슈 제외. 이전/다음 이동과 평가 행동 구분 |
| DETAIL-01 | 이슈 상세 | 카드 선택 → 3줄 요약·관점·용어·근거 조회 | 현재 issue_details 사용. 관점은 확인된 주장으로 구성 |
| ACT-01 | 관심·넘김 | LIKE/SKIP/PASS 전송 → 이벤트 저장 → 선호 반영 | 동일 이벤트 재전송은 1회 반영. 체류시간 단위 ms |
| MY-01 | 관심 목록 | 사용자·이슈별 최신 행동 조회 → LIKE 목록 | 최신 행동이 SKIP/PASS인 이슈 제외. 후속 이슈에 LIKE 자동 복사 없음 |
| REPORT-01 | 지난주 분석 | 지난주 관심 이슈 집계 → 공통 쟁점·차이 분석 → 결과 저장 | 사용자·주차당 1행. 분석 근거는 집계 대상 이슈만 허용 |
| REPORT-02 | 관심 분류 비율 | 집계 대상의 category_id별 건수 계산 | 추천 weight와 혼용하지 않음. 이슈당 한 번 집계 |
| REC-01 | 함께 살펴볼 이슈 | 관심 이슈 벡터 → 후보 검색 → 중복·비공개·행동 이력 제외 | 유사도를 동일 사건 또는 반대 관점의 증명으로 쓰지 않음 |
| REC-02 | 주요 이슈 | 공개 이슈의 공통 후보 → 중복 제외·분류 다양성 고려 | 관심 없는 관계를 별도 저장하지 않음. 부족한 후보 수를 억지로 채우지 않음 |
| PIPE-01 | 이슈 발견·생성 | 제목·description 수집 → 후보 비교 → 신규 초안 → 내용 생성 | 기존·배치 내 중복과 미공개 초안 확인 |
| PIPE-02 | 후속 전개 | 신규 사실 판정 → 새 이슈 → 근거 검증 후 FOLLOW_UP | 단순 재보도로 후속 이슈 반복 생성하지 않음 |
| OPS-01 | 자동 공개 | 본문 기반 생성 → 구조·근거 검증 → 공개 | 실패·테스트 입력은 운영 공개하지 않음 |
| OPS-02 | 작업·사용량 | 작업 상태 변경 및 외부 호출별 토큰·비용 기록 | 호출 성공과 job 성공 구분. 결과 불명 비용을 0으로 처리하지 않음 |

## 화면과 백엔드 책임

- 홈: 스와이프 중심 이슈 카드. 위/아래는 이전·다음 탐색, 좌측은 관심 없음, 우측은 관심 표시라는 기존 논의를 기준으로 한다. 실제 제스처별 SKIP/PASS 매핑과 무행동 이탈 처리는 프론트 계약에서 확정한다.
- 상세: 우리 서비스의 3줄 요약, 근거 기사, 확인된 관점, 용어 설명. 관련 법안 전용 구조는 현재 19개 테이블에 없으므로 상세 API에 지원된다고 가정하지 않는다.
- 마이: 관심 목록과 주간 보고서. 보고서 문구는 “지난주 관심 이슈를 정리했어요”처럼 집계 기간과 일치시킨다.
- 관심 목록은 LIKE 중심으로 통합한다. 별도 북마크, Apple 로그인, 사용자 정치 성향 판정은 현 ERD 범위 밖이다.

## 보고서 경험

기본안은 월요일 06:00 KST 생성, 최근 성공 보고서 4주 조회다. 4주는 조회 범위이며 삭제 기간이 아니다.

- 분석 가능한 연결이 있으면 공통 쟁점·차이와 근거 이슈를 제공한다.
- 5건 미만은 표본 부족 안내, 의미 있는 연결이 없으면 연결 없음 안내를 제공한다. 이를 생성 실패와 구분한다.
- 생성 중·실패 시 지난 성공 보고서의 실제 기간과 상태 안내를 표시한다. 지난 결과를 이번 결과로 표시하지 않는다.
- 관심 기반 확장과 주요 이슈는 분석 근거와 분리한다. 추천 결과를 주간 단위로 고정할지는 미확정이다.

## 공통 품질 요구

1. 제목이나 벡터 유사도 하나만으로 같은 이슈라고 확정하지 않는다.
2. 검증되지 않은 생성 결과를 공개 응답에 포함하지 않는다.
3. 개인 데이터 조회에는 인증된 사용자 소유 조건을 적용한다.
4. 사용자 수만큼 기사 핵심어·벡터를 다시 생성하지 않는다. 공유 이슈 가공은 재사용한다.
5. 실행 수·입력 길이·동시성·재시도 상한은 설정으로 관리한다. 수치는 공급자 검증 후 확정한다.
6. 지원하지 않는 상태 복구·열람 추적·과금 정확성을 문서나 API에서 보장하지 않는다.

구체적인 데이터 규칙은 [데이터 계약](data-contracts.md), 생성 규칙은 [파이프라인](../design/issue-pipeline.md)을 따른다.

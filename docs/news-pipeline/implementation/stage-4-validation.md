# 4단계: 생성 결과 검증

- 상태: `IN_PROGRESS` — 사용자 승인 후 구현 중
- 작성: 2026-09-20

## 기존 구현 검토

- `libs/core/src/pipeline/domain/pipeline.validator.ts`는 요약·관점·용어·세대별 영향의 형식과 기사 ID를 검사한다. 현재 3단계의 제목·사건 시각·분류 코드·점수·관점 정확히 2개·공통 조건부 영향은 모두 검증하지 않는다.
- 기존 의미 검증은 기사 내용 일치 외에 서로 겹치지 않는 독립 취재 근거 그룹을 최소 2개 요구한다. 같은 보도자료를 옮긴 여러 기사는 독립 근거 2개를 충족하지 못할 수 있다. 독립성이 불확실해도 통과하지 않는다.
- direction.md의 4단계에는 독립 근거 개수 조건이 없다. 이 조건을 유지하면 내용이 기사와 일치하는 이슈도 보류될 수 있고, 제외하면 기존 검증보다 통과 기준이 완화된다. 구현 전 사용자 결정을 받는다.
- 기존 worker는 검증 실패 시 오류 처리하며, 실패 항목만 수정하는 흐름은 없다. 새 파이프라인은 독립 실행 모듈에서 항목별 재생성을 구현하고 기존 worker와 공개 API를 변경하지 않는 안을 제안한다.
- 기존 생성 자료형과 현재 3단계 자료형도 다르므로 공통 검증기를 그대로 호출하지 않고 현재 자료형을 검증한다. 사용자 확정 사항인 관점 2개·4개 세대 코드·조건부 영향 통일을 적용한다.

## 구현 범위 및 방법

1. 완료된 3단계 실행의 GENERATED 항목을 입력으로 사용한다. 원본 초안은 유지하고 검증용 사본·판정·수정 내역을 독립 실행 기록에 저장한다.
2. 필수값·자료형·허용 DB 코드·점수 범위·계산 결과·사건 시각·기사 참조·관점 2개·세대별 영향 4개를 규칙으로 먼저 검사한다. 공통 조건부 영향이 있으면 설명과 근거가 4개 세대에서 같은지도 확인한다.
3. 규칙을 통과한 결과만 LLM으로 검증한다. 선정 기사 본문과 생성 결과를 제공해 사실 일치, 파생 정보 사이 모순, UX 라이팅 준수를 확인한다. 세대 공통 영향은 실제 영향을 받는 사람의 조건과 영향이 드러나는지도 검토한다. 기사에 없는 조건을 만들도록 요구하지 않는다.
4. 실패 결과는 수정 대상 필드·분류·이유·관련 기사 ID를 기록한다. 관점이 대립하지 않는다는 이유만으로 실패시키지 않는다.
5. 실패 필드만 한 차례 재생성하고 다시 규칙 및 의미 검증한다. 수정 허용 필드를 제한하고 원래 통과한 필드를 임의로 바꾸지 않는다. 시각·점수 등 계산값은 수정된 입력으로 재계산하고 연관 필드의 일관성도 재검증한다. 재실패 또는 입력 기사 자체의 문제는 보류한다.
6. 검증 완료/보류와 실패 이력을 기록한다. API 오류에 따른 실행 실패·재개와 내용 검증에 따른 보류를 구분한다. 체크포인트·중복 실행 방지·소유권 검증을 기존 단계 방식으로 적용한다.
7. 검증·수정 프롬프트는 별도 폴더에 둔다. 텍스트 모델은 저장소 규칙의 `gpt-5.4-mini-2026-03-17`를 사용한다.
8. 결과보고서에 최초 판정·수정 필드·최종 판정·보류 이유와 검증/재생성 호출의 토큰 및 추정 비용을 기록한다.

## 완료 조건

- 규칙 실패 시 의미 검증을 호출하지 않고, 수정 이후에만 다음 검증으로 진행한다.
- 실패 필드만 수정하며, 한 차례 수정 후 재실패한 항목은 보류한다.
- 허용되지 않은 수정·잘못된 기사 참조·허용 목록 밖 코드·범위 밖 점수·파생 데이터 모순을 검증한다.
- 영속 로컬 PostgreSQL에서 저장·재개·중복 실행 방지·소유권을 검증한다.
- 사용자 요청에 따라 새로 재실행한 1~3단계 실제 생성 결과를 대상으로 결과보고서와 비용을 확인한다.
- 기존 API·worker를 유지한다. 검증 결과의 실제 이슈 저장·공개는 5단계로 남긴다.

## 진행 상황

- 독립 검증 모듈·외부 프롬프트·마이그레이션·실행 CLI·보고서 구현 완료.
- 규칙 검증은 초안을 변경하지 않는다. 수정은 허용된 필드에만 적용하며 원본과 수정 내역을 보존한다. 점수와 사건 시각 파생값은 원본 생성 시각을 기준으로 코드에서 재계산한다.
- 단위 테스트 및 영속 PostgreSQL smoke 통과. 실제 전체 재실행 진행 중.

## 사용자 승인 및 확정 (2026-09-20)
- 독립 취재 근거 2개 조건을 새 4단계에서 제외한다. 2단계 보도 언론사 수 필터와는 별도 정책이다. 기존 공통 worker/API는 변경하지 않는다.
- 2단계 수정 및 1~3단계 전체 재실행 후 4단계를 구현·실행한다.
- 재생성 단위는 최상위 의미 필드(요약 3줄, 관점 배열 등)로 제한한다. 사건 시각/근거, 공통 영향/개별 영향, 관련 세대/분류, 용어/정의는 연결된 필드로 기록하고 함께 검증한다. 재실패는 보류한다.

## 실제 실행 중 판정 보완
- 초기 의미 검증이 공통 조건부 영향·최초 보도 시각 대체·역할 기반 관점·기사 일부에만 있는 사실을 잘못 실패 처리했다. 해당 정책 예외를 프롬프트에 명시했다.
- 3단계가 이미 사건 시각 제안을 기각하고 FIRST_REPORT로 대체했다면 기각된 제안은 감사 기록으로 보존하고 검증 모델에는 null로 제공한다. 실제 채택된 사건/보도 시각과 점수는 규칙으로 재계산 검증한다. 채택되지 않은 제안을 다시 사실로 취급하지 않는다.
- 초기 4단계 실행을 백업하고 4단계만 새로 실행한다. 1~3단계는 재호출하지 않으며 중단된 검증 비용도 합산한다.

## 용어 상한 3개 (사용자 추가 요청)
- 생성 프롬프트·JSON schema·런타임 검증에서 용어를 최대 3개로 제한한다.
- 현재 재실행에서 이미 생성한 결과는 추가 LLM 호출 없이 기존 순서의 앞 3개와 대응하는 설명만 4단계 최종 사본에 남긴다. 원본 3단계 결과와 제거한 용어 목록은 감사 기록으로 보존한다.
- 진행 중 4단계는 체크포인트부터 재개해 완료된 검증을 재호출하지 않는다. 결과보고서는 최종 사본 기준으로 표시한다.

- 추가 입력 보완: 계산 시각·점수는 코드가 검증하고 LLM 입력에서 제외한다. FIRST_REPORT의 사건 시각 필드는 응답 schema에서도 제외한다. 공통 영향은 의미 검증에 한 번만 전달하고 실제 4세대 동일성은 코드가 검사한다. 부분 수정 호출에는 원래 필드 구조를 제공한다.
- 두 번째 중단 실행 01a0bc6d-9eca-70ef-86e2-d92fe98661c1의 53회 호출까지 별도 백업했다. 두 중단 실행 75회 호출 비용을 합산한다. 최종 실행의 용어 제한 반영 중단은 같은 실행에서 체크포인트 재개했다.

## 기존 구현과 변경 방향

기존 PipelineWorker는 단일 검색어로 기사 20건을 검색하고, 최근 이슈 최대 100개와 함께 LLM에 입력해 후보 선정과 중복 판단을 한 번에 수행한다. 이어서 콘텐츠 생성까지 실행한다.

이번 구현은 별도 1단계 명령으로 실행한다. 기존 API·워커·공통 서버 구조를 유지하고, 검토 가능한 후보를 전용 테이블에 저장한다. 공개 이슈 생성 및 기존 이슈와 중복 비교는 이후 단계다.

사용자 지시(2026-09-20): 검색어별 제목만 LLM에 입력하여 후보 선정, 전체 후보를 모아 후보 간 중복 검증. Google Trends는 추후 개발로 이관하며 관련 구현은 제거한다. direction 폴더는 수정하지 않는다.

## 구현 범위와 방법

1. DB 토픽·지역·활성 정치 주체를 독립 검색어로 변환. 세대 검색은 사용자 지시로 제외.
2. 네이버 최신순 검색. 일반 탐색은 실행 기준 최근 24시간, 후속 탐색은 마지막 확인 이후 기사. 날짜 누락/미래 날짜 제외. URL 및 정규화 제목으로 중복 제거, 원문·설명은 LLM에 보내지 않음.
3. 검색어별 제목 배열만으로 정치·공공정책 관련 중요한 사건부터 최대 5개 후보를 선정하고, 다음 단계의 관련 기사 검색에 사용할 짧은 검색용 제목을 생성. 근거 제목의 배열 인덱스로 로컬 기사 메타데이터 연결. 모델은 gpt-5.4-mini-2026-03-17 고정.
4. 실행 기준 추적 중이며 기한이 남은 이슈에 한해 이슈명·지정 검색어·연결된 활성 인물/기관/정당 이름을 검색. 후보를 기존/이전 후속 제목과 비교해 명백한 새 전개만 남기고 불확실한 결과는 최종 후보에서 제외. 부모 이슈 ID 보존.
5. 후보 전체의 제목 기반 중복 검증. 사용자 지시에 따라 LLM은 중복 묶음만 응답하고, 묶음마다 대표 후보 1개를 선택한다. 중복으로 지목되지 않은 후보는 코드에서 그대로 유지한다. 대표 후보 및 모든 근거/검색어/부모 연결 보존. 기존 게시 이슈 비교(pg_trgm)는 2단계에서 구현.
6. 일자별 실행·검색 결과 체크포인트·실패 기록·완료 후보 영속화. 동시 실행 및 당일 중복 성공 방지. 실패 후 재실행 가능. 실패 시 후속 확인 시각을 전진시키지 않음.

## 실행 방법

Google Trends와 세대 검색은 제외한다. 기존 `pipelineWorker` 대신 아래 독립 명령을 사용하면 후보 저장에서 종료한다. 2~5단계·공개 API는 실행하지 않는다.

### 실행과 결과

```sh
npm run news:discovery -- run
```

필수 외부 API 설정: `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `OPENAI_API_KEY`. 네이버는 기존 NCP API Gateway 검색 클라이언트를 재사용한다. 기존 클라이언트와 같은 종류의 키가 필요하다.

- DB 토픽 표시명을 `·`로 나누고, 지역 이름 및 활성 POLITICIAN/INSTITUTION/PARTY 이름을 각각 검색한다. 문자열이 같은 검색어는 출처를 합친다.
- 검색어별 최신순 최대 50건 중 실행 시각 기준 최근 24시간 기사만 사용한다. 후속 탐색은 마지막 확인 시각 초과 기사만 사용한다. 날짜 누락·미래 기사 제외, URL·정규화 제목 중복 제거.
- 후보 추출 LLM 입력은 제목 배열뿐이다. 기사 설명·본문·URL·발행일·언론사는 전송하지 않는다. 응답의 근거 인덱스로 저장된 기사 메타데이터에 연결한다.
- 검색어별 후보 최대 5개를 선정하고 전체 후보를 모아 같은 제목은 규칙으로, 의미상 중복은 LLM으로 합친다. LLM은 중복 묶음만 답한다. 각 묶음의 keepIndex를 대표 후보로 남기고 duplicateIndexes의 후보를 합친다. 응답에 없는 후보는 그대로 유지한다. 범위를 벗어나거나 여러 묶음에 겹치는 번호는 거절한다.
- 합친 후보는 검색어·분류 출처·부모 이슈·근거를 보존한다. URL/제목이 같은 근거는 대표 기사 한 건으로 보존한다.
- `news_discovery_runs.snapshot`이 원본 기록이다. 완료 시 `.local/news-discovery/YYYY-MM-DD-candidates.json`에도 결과를 쓴다. 이 파일과 로컬 데이터는 Git에서 제외한다.
- `snapshot.results`: 검색어별 필터된 기사와 후보. `snapshot.candidates`: 최종 중복 제거 후보. `snapshot.usage`: LLM 호출별 토큰 사용량.
- 진행 로그는 `news.discovery.progress`로 처리한 검색어 수를 출력한다.

### 후속 탐색

`news_follow_up_tracks`에서 활성 상태, 추적 기한 미만, 마지막 확인 이후이며 부모 이슈가 공개된 행만 탐색한다. 이슈 제목·설정된 keywords·issue_entities에 연결된 활성 인물/기관/정당 이름을 각각 검색한다. 제목으로 명백한 새 전개만 후보로 남기고 `parentIssueIds`로 연결한다.

추적 행의 주요 값은 `issue_id`, `keywords`(문자열 JSON 배열), `last_checked_at`, `expires_at`, `known_titles`, `enabled`다. 실제 추적 대상과 기간·검색어의 자동 설정은 계획서 3단계에서 구현한다. 1단계는 이미 설정된 추적 행을 소비한다. 후보는 기존 `issue_relations`에 즉시 공개하지 않는다.

### 실패와 재실행

같은 KST 날짜에 실행하면 완료 결과를 재사용한다. 실패한 날 다시 실행하면 저장된 검색 결과 다음부터 재개하며 원래 실행 시각·설정·검색어를 유지한다. 실패 시 추적 확인 시각은 전진하지 않고, 전체 완료와 확인 시각 갱신은 하나의 DB 트랜잭션으로 처리한다.

동시 실행은 DB에서 차단한다. 프로세스가 강제 종료되면 heartbeat가 5분 이상 끊긴 실행을 재확보할 수 있으며 이전 실행자의 저장은 차단한다. SIGINT/SIGTERM은 현재 외부 호출 이후 종료 체크를 거쳐 실패 상태로 남긴다. 외부 호출은 네이버 10초, OpenAI 120초 제한이다. 네트워크 전송 후 결과 기록 전에 종료된 호출은 재시도 시 과금이 중복될 수 있다.

다른 KST 날짜에 실행하면 새 탐색을 시작한다. 전날 미완료 실행의 결과는 보존되지만 자동 재개하지 않는다. 검색어/후보가 설정 상한을 넘으면 누락시키지 않고 실패 처리한다.

### 검증과 운영

```sh
npm run test:jest -- test/unit/newsDiscovery.test.ts
node scripts/news-discovery-smoke.mjs
```

`smoke`는 고정된 로컬 DB에서만 동작하고 네이버·LLM은 대역을 사용한다. 검증용 행과 실행 기록은 로컬 DB에 남긴다. 검증용 정치 주체는 종료 시 비활성화한다.

운영은 명시적인 DB 환경변수를 설정하고 `npm run news:discovery -- migrate`, `npm run news:discovery -- run`을 사용한다. 정확한 일일 실행 시간과 스케줄러 연결은 운영 환경 확인 후 결정한다. 이번 작업에서는 운영 배포·스케줄 등록을 하지 않았다.

## 사용자 검토 반영: 중요 이슈와 검색용 제목 (2026-09-20)

- 구현 범위: 검색어별 후보 상한을 설정·LLM 요청·서비스 검증에서 최대 5개로 고정한다. 제목에서 드러나는 공공 영향, 정책/법률 변화, 구체적인 결정·집행을 기준으로 중요한 후보부터 선택한다. 5개를 억지로 채우지 않는다.
- 후보 `title`은 기사 헤드라인이나 화면용 제목이 아닌 다음 단계의 네이버 검색어다. 핵심 주체·사건·행동을 남긴 짧은 명사구(3~7개 핵심어 권장, 최대 60자)로 작성한다. 구별에 필요한 시기·지역은 유지하고 수식·인용·부가 수치는 제외한다. 제목에 없는 사실은 추가하지 않는다.
- 예: `행안부, 8월 호우 피해 이재민 주거 안정 지원… 복구비 2,308억 원 투입` → `행안부 8월 이재민 주거 지원`.
- 변경 파일: discovery.model.ts, discovery.policy.ts, discovery.service.ts, discovery.types.ts, 전용 단위 테스트와 본 구현·검증 문서. 기존 `title` 필드 구조는 유지한다.
- 완료 조건: 6개 이상 설정/출력 거절, 60자 초과 제목 거절, 기존 제목만 입력 계약·중복 처리 유지, 실제 모델의 짧은 검색어 생성 확인. 기존 완료 DB 실행은 재작성하지 않는다.

### 검토 반영 검증 결과

- 완료: 설정/모델 호출에서 6개 이상 제한 거절, 서비스에서 초과 출력 거절. 기본 상한 5개 유지.
- 짧은 검색어 제목을 응답 스키마와 서비스에서 최대 60자로 제한하며 공백을 정리한다. 원래 기사 제목과 메타데이터는 근거에 그대로 보존한다.
- 전용 단위 테스트 14개, 배치 빌드, 타입 검사, 변경 파일 ESLint, 실제 DB smoke 통과.

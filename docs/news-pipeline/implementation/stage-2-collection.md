# 2단계 이슈별 기사 수집 및 선별

- 상태: `APPROVED` — 사용자 검토·승인 완료
- 작성·갱신: 2026-09-20
- 기존 구현 비교 후 사용자 승인: 별도 2단계 처리, 설정 파일 기반 언론사 우선순위, 미등록 언론사 후순위, 동순위 최신순.

## 범위와 구현 방법

1. 완료된 1단계 실행 ID를 입력받는다. 후보·출처·부모 이슈 연결을 보존한다.
2. 현재 실행 기준 지난 7일간 공개된 이슈만 `pg_trgm` 제목 유사도 순 상위 10개 조회한다. 생성일이 아닌 `published_at`을 사용한다. LLM은 같은 사건의 중복만 기존 이슈 번호로 반환한다. 새로운 전개는 유지한다.
3. 후보의 검색용 제목으로 네이버 최신 기사 50건을 조회한다. 최근 7일, URL·제목 중복 제거 후 대표 기사 제목과 검색된 기사의 제목·검색 요약으로 LLM이 동일 사건의 기사 번호를 고른다. 1단계 후보 추출의 제목 전용 입력은 유지한다.
4. 원문 URL의 호스트를 설정 파일에 매칭해 언론사 우선순위, 최신순, URL 순으로 최대 5건을 선택한다. 목록은 운영 편집 기준의 초기 설정이며 객관적인 신뢰도 순위가 아니다. 동일 우선순위는 동일 대우하고 미등록 언론사도 제외하지 않는다.
5. 관련 기사 1개 이하는 `INSUFFICIENT_ARTICLES`, 기존 이슈 중복은 `DUPLICATE`, 2~5개는 `SELECTED`로 기록한다.
6. 실행 시간·설정·비교 대상·검색 기사·관련성 판단·선정 결과·토큰 사용량을 별도 DB 스냅샷에 저장한다. 단계별 체크포인트, 임대 잠금과 heartbeat로 재시작/중복 실행을 방어한다. 완료 실행 재요청은 기존 결과를 반환한다.

## 제외·남은 사항

- 본문 다운로드 및 파생 데이터 생성은 3단계에서 수행한다. 여기서 선정한 기사 수는 본문 수집 성공 수를 의미하지 않는다.
- 실제 이슈 생성·공개, 스케줄러, Google Trends는 범위 밖이다.
- 운영 DB 확장 설치 권한·운영 네트워크·스케줄러는 별도 검증한다.
- 1단계 기존 완료 데이터는 변경하지 않는다. 예전 실행에는 검색용 제목 규칙 적용 전 제목이 남아 있을 수 있다.
- 언론사 초기 목록과 실제 선정 결과는 구현 후 사용자 검토 대상이다.

## 구현 결과와 실행 방법

- 계획한 2단계 전용 처리 구현 완료. 기존 API와 공개 worker는 변경하지 않았다.
- 초기 우선순위는 설정에 등록한 22개 언론사 동순위(`10`), 미등록 언론사 후순위다. 등록 언론사끼리 서열을 두지 않으며, 숫자가 작을수록 먼저 선정한다. 이름이 아닌 원문 URL 도메인과 하위 도메인으로 판별한다.
- 네이버 URL만 남아 원문 언론사를 알 수 없는 기사는 미등록으로 취급한다. 동일 언론사 기사 개수를 별도로 제한하지 않는다.
- 새 실행의 설정·기준 시각을 저장한다. 실패 재개는 저장된 설정·시각을 사용하며, 완료된 1단계 실행에 대한 2단계 재요청은 기존 결과를 반환한다. 설정 변경은 새 1단계 실행에 적용된다.
- `DUPLICATE`는 기존 중복 이슈 ID, `INSUFFICIENT_ARTICLES`는 관련 기사 인덱스, `SELECTED`는 선정 기사 2~5건을 남긴다. 부모 이슈·검색 출처는 모두 유지한다.
- CLI 결과는 `.local/news-collection/<1단계 실행 ID>-articles.json`으로 내보낸다. DB가 원본이며 파일은 검토용이다.

```sh
npm run build:batch
npm run news:collection -- migrate
npm run news:collection -- plan
npm run news:collection -- run <완료된-1단계-실행-UUID>
node scripts/news-collection-smoke.mjs
```

## 사용자 피드백 반영 계획

- 대표 기사 제목을 하나 명시해 관련성을 판단한다. 같은 주제라도 별도 행사·발표·결정·지역·시점의 사건이면 제외하고 대표 기사와 동일한 사건/전개의 보도만 남긴다. 판단 불가도 제외한다.
- 관련성 입력은 검색용 제목, 대표 기사 제목, 검색된 각 기사의 제목·검색 요약이다. 여러 근거 제목을 동등한 비교 기준으로 제공하지 않는다.
- 신규 후보의 대표 기사를 사용한다. 기존 저장 후보에는 대표 필드가 없으므로 첫 근거 기사를 호환용 기준으로 사용한다. 대표 근거가 아예 없으면 모델을 호출하지 않고 오류로 처리한다.
- 2단계 기사 기간은 7일로 변경한다. 검색은 기존처럼 최신순 최대 50건이며 1단계는 24시간을 유지한다.
- 변경 예정: collection 모델·서비스, 관련 단위 테스트. 기존 완료 결과는 자동 변경하지 않는다.
- 완료 조건: 대표 기사 입력·사건 구분·7일 경계·미래/8일 전 기사 제외 검증, 실제 로컬 PostgreSQL 연동 및 실제 LLM 표본 확인.


## 피드백 반영 완료

- 대표 기사 선택·보존, 대표 제목 기준의 동일 사건 선별, 2단계 7일 기간 적용 완료.
- 기존 완료 실행은 그대로 두었다. 기존 결과 보고서의 50개 선정/75개 제외는 이전 규칙 결과이며 이번 규칙의 결과가 아니다.

- 제목 생성 표본에서 사건 특정성이 개선됐으나 `서울 전역 토허제`처럼 전개가 빠지는 경우도 남았다. 프롬프트만으로 모든 후보의 편집 품질을 보장하지 않으므로 다음 전체 실행 결과 검토 시 확인해야 한다.


## 단일 언론사 제외 (2026-09-20)
- 기존에는 관련 기사 2개 이상이면 선정했다. 사용자 요청에 따라 관련 기사 전체의 보도 언론사가 2곳 미만이면 INSUFFICIENT_PUBLISHERS로 제외한다. 무관한 기사는 언론사 수에 포함하지 않는다.
- 설정에 등록된 동일 언론사의 도메인·서브도메인은 한 곳으로 묶고, 미등록 언론사는 정규화된 제공 언론사명(없으면 호스트)으로 센다. 이는 독립 취재 여부 판단과 별개다.
- 변경 범위: collection 정책·서비스·타입, CLI/보고서, 단위 테스트. 기사 선정 우선순위와 최대 5개는 유지한다. 판정은 상위 5개로 자르기 전 관련 기사 전체 기준이다.
- 완료 조건: 여러 기사/동일 언론사 제외, 관련 기사에만 언론사 수 적용, 두 언론사 통과 및 재개를 확인하고 전체 1~3단계를 재실행한다.

## 기존 테이블 검색 인덱스 제거 (2026-09-20)

- 사용자 요청으로 `issues` 검색 인덱스 생성을 DDL에서 제거한다. 기존 테이블 컬럼·인덱스를 추가하지 않는다.
- 제목 유사도는 기존 7일 필터·상위 10개 쿼리로 계속 조회한다. `pg_trgm` 확장은 유사도 연산에 필요하여 유지한다. 별도 검색 테이블은 만들지 않는다.
- 이미 적용된 인덱스를 제거할 선택 SQL과 로컬 DB 인덱스 삭제를 수행한다. 인덱스 없는 상태에서 수집 스모크 테스트를 확인한다.

## 별도 제목 검색 테이블 (2026-09-20)

- 사용자 추가 요청으로 인덱스 없는 직접 조회 대신 `news_issue_search`에 이슈 ID·제목·공개 시각을 복사하고 해당 테이블에 GiST 제목 인덱스를 둔다. 기존 `issues`는 조회만 한다.
- 2단계 새 실행·재개 시 저장된 실행 기준 시각의 최근 7일 공개 이슈를 트랜잭션 안에서 동기화한다. 삭제·비공개·기간 밖 이슈는 제외하고 제목 변경도 반영한다. 완료 실행 재사용 시에는 동기화하지 않는다.
- 동기화와 실행 점유는 같은 advisory lock으로 직렬화한다. 후보별 검색은 복사한 목록만 조회한다. 외래키·트리거는 추가하지 않으며 실행 중 원본 변경은 다음 동기화에서 반영한다.
- SQL DDL·수집 저장소·스모크 테스트·러너 문서를 수정하고 신규/수정/비공개/삭제 반영과 기존 검색 결과를 검증한다.

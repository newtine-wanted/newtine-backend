# LLM 파이프라인 구축 방향성 수립

## 개요
정치 유관 뉴스 데이터를 수집·처리하는 비용 효율적인 LLM 파이프라인 구축

## 파이프라인 설계 방향 기록
> 이슈 중심 탑다운 수집 방식 채택
> 사유: 데이터가 증가해도 지속가능한 구조 수립

- 이슈 수집: 이슈를 먼저 선정하고, 이슈별로 관련 기사를 수집한다.
  - 기사를 먼저 수집한 뒤 누적된 모든 이슈와 일치 여부를 비교하는 방식은 데이터가 증가할수록 처리 비용이 커짐.
- 후속 보도 : 기존 이슈 중 후속 보도를 추적할 대상을 미리 선정하고, 해당 이슈를 기준으로 후속 기사를 검색한다.
  - 최초 이슈 선정 시 후속 보도 가능성을 판단해 추적 여부와 추적 기간을 함께 설정한다.
  - 새로운 전개가 확인되면 후속 이슈를 생성하고 기존 이슈와 연결한다.

## 파이프라인 처리 단계
1. 대상 이슈 탐색 및 선정
2. 이슈별 기사 수집 및 선별
3. 이슈 파생 데이터 생성
4. 생성 결과 검증
5. 이슈 저장 및 공개

### 1. 대상 이슈 탐색
아래 세 가지 방법으로 트렌드 파악 + 이슈 후보 선정. 검색할 카테고리는 작성 후 검토받을 것.
1. **Google Trends 수집**(추후개발)
   - 목적: 전반적인 정치 이슈 트렌드 파악하여 이슈 후보 선정
   - 수집 방법:
     - 한국 기준 Trending Now CSV를 하루에 한 번 수집
     - 수집한 용어를 다시 네이버 뉴스 API로 탐색하여 구체적인 이슈 선정
   - 수집 카테고리: Law and Government, Politics
   - RSS는 카테고리 지정 불가능으로 제외, CSV는 공식 내보내기 기능이지만 전용 API는 아님.

2. **카테고리 기반 네이버 뉴스 API 탐색**
   - 목적: 사용자 취향의 세대·지역·이슈·인물 및 기관까지 폭넓게 수집하여 이슈 후보 선정
   - 수집 방법:
     - DB 카테고리를 검색어로 변환해 네이버 뉴스 API에서 최신순 검색 (최대 50개)
     - 조합을 검색하지 않고 각 분류를 개별 검색
     - 최근 24시간 기사만 수집한 뒤 URL과 제목으로 중복 제거
     - 제목만 LLM에게 넘겨 이슈 후보 선정 (검색어당 최대 3개)
     - 검색어별로 취합된 이슈들은 LLM에게 넘겨 중복 제거.

3. **후속 보도 탐색**
   - 후속 보도 추적 대상으로 지정된 기존 이슈만 검색
   - 이슈명·관련 인물·기관·검색어를 이용해 네이버 뉴스 검색
   - 마지막 확인 이후에 나온 기사만 수집
   - 새로운 내용이 확인되면 기존 이슈와 연결된 후속 이슈 후보 생성
   - 추적 기한이 끝나면 검색 중단

### 2. 이슈별 기사 수집 및 선별
저가 LLM 개입. 중복 제거 시 **지난 일주일간 게재된 이슈 중 PostgreSQL 제목 유사도 상위 10개**만 비교하여 토큰 낭비를 줄인다. pg_trgm 확장 사용.
1. 1단계에서 수집한 이슈 후보마다 PostgreSQL 제목 유사도 상위 10개를 조회하고, 저가 LLM으로 중복 여부 판단
2. 네이버 뉴스 API에 이슈 검색
3. 검색된 기사 중 무관한 기사 제거, 언론사 저명도 기준 최대 5개 기사 선정
4. 1개 이하 검색된 이슈는 버림

### 3. 이슈 파생 데이터 생성
생성되는 모든 텍스트는 [뉴틴 UX 라이팅 가이드](./ux-writing.md)를 따른다.
1. **핵심 정보 생성**
   - 선정된 기사 최대 5개를 한 번에 입력. (추후 비용과다 시 변경 가능)
   - 제목·사건 주요 시각·요약 본문 생성
   - 기사에 없는 사실은 추가하지 않음
   - 사건 시각이 불명확하면 최초 보도 시각 사용
2. **분류 정보 생성**
   - DB에 등록된 값 중에서만 선택
   - 토픽·지역·인물·기관은 규칙으로 먼저 매칭
   - 판단이 어려운 항목만 LLM 사용
   - 관련 세대는 복수 선택 가능
3. **평가 정보 생성**
   - LLM 대신 계산식 사용
   - 중요도는 이슈 검색 당시 검색된 기사 수·보도 언론사 수·LLM 추정 중요도을 반영
   - 최신성은 사건 주요 시각을 기준으로 계산
4. **세부 정보 생성**
   - DB의 세대별 영향 작성
   - 영향이 없으면 없다고 쓰면 됨
   - 관점별 정리는 이해관계자 기준으로 2개 작성
   - 선정된 기사에서 확인되는 내용만 사용
5. **용어 정보 생성**
   - 생성된 내용에서 어려운 용어 추출
   - 기존 용어 테이블을 먼저 검색 (LLM 미사용)
   - 새로운 용어만 설명 생성 (LLM 사용)
   - 설명은 짧고 쉽게 작성
6. **후속 보도 추적 설정**
   - 후속 보도가 예상되는지 판단
   - 예상되면 추적 기간과 검색어 설정
   - 이후 배치에서 후속 보도 탐색 대상으로 사용

### 4. 생성 결과 검증
규칙 기반 검증을 먼저 수행하고, 통과한 결과만 준수한 성능의 LLM으로 검증한다.

1. 필수값·데이터 형식·DB 코드·점수 범위 검증
2. 생성된 내용이 선정 기사와 일치하는지 검증
3. 파생 데이터 사이에 모순이 없는지 검증
4. UX 라이팅 기준 준수 여부 검증
5. 실패한 항목만 다시 생성하고, 재실패하면 보류
6. 검증 결과와 실패 사유 기록

### 5. 이슈 저장 및 공개

## 실행 주기

- 전체 이슈 탐색 파이프라인은 하루에 한 번 실행하는 것을 권장한다.
- 정확한 실행 시간은 서버 운영 환경을 확인한 뒤 결정한다.

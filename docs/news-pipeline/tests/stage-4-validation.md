- 아래 기존 실행 기록은 이전 의미 검증 정책의 이력이다.

## 시나리오

1. 형식·DB 코드·점수·근거 ID 검증. 규칙 실패 시 최초 표현 검증 호출 생략.
2. 공격적·편향적 표현만 검사하며 사실·모순·일반 UX 판정은 거부.
3. 실패한 필드만 1회 수정, 원본 보존, 다른 필드 수정 거부.
4. 수정 후 재실패 또는 형식 오류는 HELD, 재수정하지 않음.
5. 마지막 표현 검증 API 실패 후 재개 시 이전 검증·수정 호출 재사용.
6. DB에서 완료된 3단계만 입력 허용, 동일 입력 완료 결과 재사용.
7. 실행 중복 차단, 만료 소유자 저장·완료 거부, 기존 소유자의 fail 무효.
8. 기존 공개 이슈 개수 불변 및 실제 공개 없음.

## 남은 품질 검토

- 보류 27개를 모두 실제 사실 오류로 단정할 수 없다. LLM이 정상 정책이나 선택적 문체 개선까지 실패로 분류하는 과잉 판정이 남아 있다.
- 예: ‘현대건설, 도시정비 수주 2년 연속 10조 돌파’의 최종 title 판정은 이유에서 핵심 사실이 일치하고 명백한 오류가 없다고 설명하면서 실패 항목으로 반환했다. 이 결과를 임의로 통과시키지 않고 HELD와 원문 판정을 보존했다.
- 이해관계자 주체가 모호하거나 분류가 기사와 맞지 않는 등 검토할 만한 지적도 함께 있으므로, 보류 목록의 실제 내용 오류와 검증기 오판을 구분해 사용자 검토가 필요하다.
- 보완을 위해 전체 1~3단계를 추가 재호출하지 않았다. 초기 검증 2회를 보관하고 4단계 입력만 개선해 새로 검증했다. 최종 실행 중 사용자 용어 상한 요청과 출력 한도/일시 외부 오류는 체크포인트에서 재개했다.

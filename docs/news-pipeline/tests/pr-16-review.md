# PR #16 리뷰 수정 검증 (2026-09-20)

## 반영 내용

- 수집 저장소의 조회·저장·상태 전환·검색 복사를 MikroORM으로 변경하고 core Issue 매핑을 재사용했다. 전용 매핑은 독립 CLI에만 등록한다. API 등록·기존 테이블은 변경하지 않는다.
- 유사도 조회도 ORM QueryBuilder 한 번으로 실행한다. PostgreSQL 고유의 `similarity`/거리 연산과 실행 점유용 advisory lock만 SQL 표현으로 남긴다.
- DDL의 DO·단계적 ALTER를 제거하고 최종 테이블·인덱스·제약만 정의한다. 002/003 초기화 SQL은 삭제하고 `scripts/news-pipeline-prepare.mjs` 및 TypeScript 서비스로 대체했다.
- 타이머는 긴 외부 호출 중 5분 점유 만료를 막는 30초 heartbeat라 유지했다. 코드와 안내에 이유를 적고 실제 타이머 동작을 가상 시간으로 검증했다.

## 결과

- 타입 검사·배치 빌드·lint 통과.
- 뉴스 단위 테스트 83개 및 러너 테스트 6개 통과.
- 310초 외부 응답 대기 중 heartbeat 10회, 실행 완료 후 타이머 0개 및 추가 heartbeat 없음 확인.
- 최종 ORM 수집 스모크 통과: 유사도 상위 10개·기간·정렬·검색 동기화, 중복/부족/선정, 완료 결과 재사용, 실패 재개, 점유 만료·소유권 보호.
- 초기화 스모크 통과: 새 용어 저장, 기존 설명 유지, 모호한 정의·비공개 이슈 제외, 검색 복사, 두 번 실행, 원본 데이터 불변. 테스트 fixture는 전체 트랜잭션 롤백.
- 최종 DDL을 새 검증 DB와 데이터가 있는 영속 DB에 두 번 적용했다. 테이블 7개 및 검증 모드 제약 확인, 기존 실행/이슈 건수 보존. 임시 DB는 삭제했다.
- 초기에 ORM 정렬 형식 및 테스트 fixture의 DB 요약 형식 오류가 발견되어 수정 후 재검증했다.
- 운영 DB 적용 및 유료 AI 호출 없음.

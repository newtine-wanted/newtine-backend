# 의사결정 기록

- 정리일: 2026-09-12
- 기준: 대화에서 수정한 Notion ERD v1.2
- 목적: 구현 전에 확정한 선택과 아직 닫지 않은 결정을 한 곳에서 관리한다.
- 대상: 백엔드 개발자, 콘텐츠 파이프라인 개발자, 기획자

이 문서는 특정 코드를 어떻게 작성하는지 설명하는 설계 문서가 아니라, 왜 그 방향을 선택했는지와
무엇이 아직 미정인지 기록한다. 구현 방법은 [구현 설계](../design/README.md), 반복해서 적용하는
규칙은 [구현 컨벤션](../conventions/README.md), 서비스와 데이터의 외부 계약은 [정책과 계약](../policies/README.md)에서
관리한다.

## 판단 기준

문서 간 충돌이 생기면 다음 순서로 확인한다.

1. 최근 대화에서 명시적으로 확정한 결정
2. ERD v1.2
3. 이슈 생성 파이프라인 계약
4. 백엔드 구현 문서
5. 화면 표현

서로 다른 정책을 임의로 합치지 않고, 충돌하는 문서는 이 기록에 결정 근거를 남긴 뒤 갱신한다.

## 확정 결정

| 항목             | 결정                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 서비스 중심 단위 | 기사와 이슈를 구분한다. 카드는 이슈를 표현한다.                                                |
| 이슈 발견        | 제목·description으로 후보를 추출한 뒤 기존 이슈와 비교한다. 신규 확정 후 관련 기사를 수집한다. |
| 동일 이슈        | 단순 재보도는 새 이슈·생성 job을 만들지 않는다.                                                |
| 후속 전개        | 새 `issue_id`로 생성하고 검증된 `FOLLOW_UP` 관계로 연결한다.                                   |
| 기사 연결        | `issue_articles`는 근거 기사 전용이다.                                                         |
| 가공 결과        | `issue_details`에 현재 상세 1벌을 둔다. 전체 버전 스냅샷은 누적하지 않는다.                    |
| 본문             | 본문 영구 저장 테이블은 두지 않는다. 재시작 시 입력을 다시 확보할 수 있다.                     |
| 분류             | `issue_categories` 값 테이블과 대표 `category_id`를 사용한다.                                  |
| 행동             | `LIKE` / `SKIP` / `PASS`만 기록한다. `dwell_time`은 밀리초다.                                  |
| 보고서           | 마이페이지에서 지난주 보고서를 제공한다. `weekly_reports`에 상태·결과를 저장한다.              |
| 공개             | 검증을 통과한 초기 생성 결과는 자동 공개한다.                                                  |
| 개발 입력        | 실제 본문 공급 경로는 미확정이다. 테스트용 본문으로 계약부터 검증한다.                         |
| 저장소           | PostgreSQL을 사용한다. 임베딩은 pgvector 활용 방향이며 모델·차원은 미정이다.                   |

## 미확정과 현재 한계

- 본문 공급, 추천 점수, 워커 종료 확인, 보존 기간은 구현 단계별로 결정한다.
- 행동 없이 열람만 한 이슈까지는 정확하게 추적하지 못한다.
- `stage`만으로 검색 결과·본문·생성 중간값을 복구할 수 없다.
- 사용자별 추천 결과와 주차별 주요 이슈 목록을 고정 저장하는 구조는 아직 없다.
- AI 사용량 기록만으로 엄격한 동시 예산 예약이나 보고서별 비용 추적을 보장하지 않는다.

새 테이블이나 운영 정책을 자동으로 추가하지 않고 [구현 계획](../design/implementation-plan.md)의 미결정
목록에서 닫는다.

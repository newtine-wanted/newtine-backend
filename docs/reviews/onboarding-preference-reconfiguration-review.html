범위와 의도

기존 POST /api/me/onboarding/complete를 PENDING·SKIPPED·COMPLETED 모두에서 full replacement로 동작시키고, 별도 snapshot table 없이 category aggregate와 known action contribution에서 topicCodes·entityIds를 계산하는 변경을 검토했다.

user_interaction_events와 user_issue_contributions를 삭제하지 않고, 기존 category action 합계에 새 onboarding base를 다시 적용하는 것이 핵심 불변식이다.

발견 사항

findings and reclassification
ID 심각도 상태 근거와 영향 최소 조치
REV-001 P2 · 검증 보강 non-blocking 이전 리뷰에서 실제 PostgreSQL 경로 미검증을 P1 blocker로 분류했지만 과했다. onboarding.service.ts:32-40가 top-level transaction을 소유하고, postgresOnboarding.repository.ts:523-545가 ambient transaction context를 사용하며, complete/action 양쪽이 user row를 잠근다. 기존 PostgreSQL·Compose smoke와 transaction-manager 검증도 있어 구현 wiring 자체의 결함은 확인되지 않는다. 다만 이 변경의 새 overwrite/rollback 시나리오를 직접 수행하는 DB smoke는 없다. release 전 disposable PostgreSQL에서 overwrite, action/event 보존, GET derived response, 중간 INSERT 실패 rollback을 한 번 더 확인하면 된다. merge blocker는 아니다.
REV-002 P2 · 테스트 보강 non-blocking 기존 동일 payload retry 테스트가 다른 payload overwrite 테스트로 바뀌었다 (test/unit/onboarding.test.ts:103-132). 현재 테스트는 같은 payload를 두 번 보냈을 때 action/base가 누적되지 않는다는 핵심 멱등성 계약을 직접 증명하지 않는다. 다만 구현은 매번 현재 action 합계 + 선택 base로 delete/reinsert하고 완료 시각을 보존하므로, 현재 코드에서 누적 버그가 관찰된 것은 아니다. 동일 payload를 두 번 보낸 뒤 topic/entity/region weight와 completedAt이 동일한 회귀를 추가한다. acceptance blocker가 아니라 회귀 방지용 보강이다.
REV-003 P2 해결됨 설계 계약은 topic catalog/order, entity id, region code 기준의 안정된 순서를 요구했다. production GET을 topic issue_categories.display_order와 region code 순서로 고쳤고, InMemory adapter도 같은 contract로 맞췄다. 해결: SQL/InMemory 정렬 회귀를 추가했다.
REV-004 P2 해결됨 residual anomaly에 user id와 category별 aggregate/action/residual context를 담고, global exception filter가 이를 내부 diagnostic.onboarding에 기록하도록 고쳤다. HTTP response에는 기존처럼 generic 500만 노출한다. 해결: exception logging 회귀를 추가했다. metric/alert 연결은 운영 설정 범위다.
REV-005 해당 없음 철회 이전 지적은 정상 상태 전이를 벗어난 stale row를 전제로 했다. 유효한 writer에서는 skipOnboarding이 timestamp를 NULL로 만들고, complete는 COMPLETED overwrite의 기존 timestamp만 보존한다. legacy 데이터 정합성 검사를 범위에 넣지 않는 한 구현 결함으로 볼 근거가 없다. 별도 수정 불필요. legacy 상태 정합성을 별도 운영 범위로 잡을 때만 데이터 점검을 추가한다.

검증 증거와 공백

  • focused onboarding·adapter·exception tests: 31개 통과.
  • unit tests: 47 suites / 246 tests 통과.
  • contracts, generated typecheck, format, lint, build 통과.
  • integration: 2 suites / 11 tests 통과, DB 환경 의존 3 suites는 skip.
  • 새 onboarding overwrite/rollback 전용 PostgreSQL smoke는 미실시. 이는 transaction wiring blocker가 아니라 정확한 새 SQL branch의 선택적 coverage gap이다.
  • 서비스 transaction boundary, repository의 ambient transaction context, user row lock, 기존 PostgreSQL/Compose smoke 및 transaction-manager 회귀를 확인했다.
잔여 위험: 새 overwrite SQL branch의 직접 DB smoke가 없고, anomaly metric/alert 연결은 운영 설정에서 확인해야 한다. 모두 non-blocking risk이며, 현재 구현에서 transaction 연결 단절이나 데이터 삭제 결함은 확인되지 않았다.

리뷰 판단

판정: blocker 없음. REV-001은 P1 오탐/과대 분류로 철회하고 exact DB smoke 보강으로 낮췄다. REV-002는 코드 결함이 아닌 멱등성 회귀 테스트 공백으로 P2에 남겼다. REV-003(순서 계약)과 REV-004(anomaly 운영 진단)는 구현·회귀 검증으로 해결했고, REV-005는 정상 상태 범위 밖의 가정이라 철회한다.

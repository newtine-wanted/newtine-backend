목적
승인된 env-first 모델 선택과 공통 fallback을 구현하고 pipeline·report worker의 실제 요청·운영 설정을 검증한다.
사용자
NEWTINE 백엔드 개발자와 batch 운영자
문제
모델 선택이 pipeline YAML과 report 필수 env로 분리되어 있어 환경별 모델 교체와 기본 실행이 일관되지 않다.
핵심 흐름
기준선 확인 → resolver·default 구현 → 운영 설정 연결 → focused 회귀 → 전체 정적·빌드 게이트

승인된 범위: PIPELINE_AI_MODEL과 REPORT_AI_MODEL의 precedence/fallback, 공통 기본값, 관련 문서·Compose·테스트. API 계약·embedding·DB·실제 OpenAI 호출은 범위 밖이다.

기준선구현상태이슈검증공백잔여 위험이해 점검제어 상태

1. 기준선·Execution Contract

Goal
pipeline text는 env → stage YAML → 공통 기본값, report text는 env → 공통 기본값 순서로 모델을 결정한다.
Invariants
공백 env는 미설정, 실제 provider payload와 usage model은 resolved model 기준, API key·embedding 정책 유지.
검증 명령
npm run test:jest -- test/unit/reportOptions.test.ts test/unit/pipelineAiConfiguration.test.ts test/unit/openAiProvider.test.ts test/unit/reportProvider.test.ts 후 npm run format:check, npm run lint, npm run typecheck, npm run build
금지
사용자 .env 값 변경, API body model 추가, embedding 정책 변경, DB migration, 실제 OpenAI 호출, unrelated generated artifact 수정.

3. 구현 상태

기술 구현 완료. 승인된 코드·운영 설정·focused regression 범위를 구현했고 전체 unit suite, format·lint·typecheck·build까지 통과했다. 실제 OpenAI 호출은 실행하지 않았다.

6. 검증 공백

  • 실제 OpenAI endpoint와 실제 모델명 유효성은 외부 호출 금지 범위라 검증하지 않았다.
  • integration suite와 Compose acceptance는 이번 설정 변경의 범위를 넘어 실행하지 않았다.
  • 운영 배포 환경에서 env 주입이 실제로 적용되는지는 별도 운영 preflight가 필요하다.
  • 개발자 이해 점검 결과는 아직 관찰되지 않았다.

7. 잔여 위험

사용자가 존재하지 않는 모델명을 env에 넣으면 fallback하지 않고 provider에 전달되어 upstream 오류가 발생한다. 이는 env override를 존중하기 위한 의도된 동작이며, 모델명 유효성 검사는 이번 범위에 포함하지 않는다.

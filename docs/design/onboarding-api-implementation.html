As-built 흐름

현재 구현

옵션·entity catalog는 읽기 전용 port로 분리하고, 온보딩 write는 repository port와 transaction manager를 통해 수행한다. production provider는 PostgreSQL adapter로 연결되어 users 행 잠금, master validation, preference upsert, terminal 상태 변경을 한 transaction에서 수행한다. 런타임 인증은 JwtAuthGuard가 검증한 AuthPrincipal을 @CurrentUser() decorator로 controller에 전달하며, 온보딩 write는 그 principal의 userId만 사용한다. 테스트는 fake principal과 repository를 직접 주입한다.

검증 공백

generated SDK/OpenAPI/E2E는 새 metadata 경로와 전역 /api prefix를 함께 반영해 재생성·검증했다. 다만 generated stability check는 현재 변경이 아직 HEAD에 커밋되지 않아 기존 HEAD와의 drift를 보고하므로, 커밋 후 CI에서 재확인해야 한다. 이번 수정은 로컬 단위·타입·API build와 운영 DB 컬럼 증거를 확인했지만, 수정된 revision의 실제 Cloud Run 배포와 production DB-backed entityIds complete smoke는 아직 실행하지 않았다. Docker Desktop 메모리 부족으로 local Compose DB-backed smoke도 미완료다. production PostgreSQL base migration과 실제 운영 데이터에 대한 호환성, 실제 인증 principal, 운영 대상 명단 적재, 설정 수정 API는 이번 구현에서 검증하지 않는다. delta migration은 기존 users/entities 등 base table이 먼저 존재하는 환경을 전제로 하며, 기존 category taxonomy가 12개 승인 code로 정규화되지 않으면 fail-closed한다.

잔여 위험

임시 PostgreSQL fixture에서 영속 저장과 행 잠금은 확인했지만 production base schema에 적용하기 전 호환성 확인이 필요하다. 기존 10개 분류가 다른 명칭으로 운영 중이면 별도 legacy mapping migration이 먼저 필요하다. 운영 entity master seed와 인증 provider도 별도 운영 절차가 필요하다. 전역 /api prefix와 생성 계약 재생성은 다른 세션의 완료 결과와 합쳐서 최종 확인해야 한다.

구현 이해 점검

상태: 실시. principal이 없을 때는 controller가 body/query의 userId를 사용하지 않고 401을 반환한다. terminal 재요청은 repository의 상태 확인이 가중치 반영보다 먼저 실행되어 저장 snapshot을 그대로 반환한다. complete와 skip이 동시에 들어오면 저장소의 첫 terminal 전이가 승자가 된다. PostgreSQL adapter는 users 행을 FOR UPDATE로 잠근 뒤 topic/entity/region master를 확인하고 preference와 상태를 함께 변경한다. 임시 PostgreSQL fixture에서 이 흐름을 확인했으며, production base migration·인증 연결 전 운영 활성화는 보류한다.

구현 제어 상태

운영 제어 보류. metadata source controller/service, response mapping, module wiring과 focused test는 완료했다. 운영 DB의 user_entity_preferences_id 컬럼에 맞춘 raw SQL·EntitySchema 정합화와 회귀 assertion도 완료했다. 전역 /api prefix를 포함한 generated contract 재생성·검증도 완료했지만, 현재 working tree는 여러 세션의 변경이 섞인 미커밋 상태다. 새 revision 배포 및 실제 production complete smoke, production base migration, authentication provider, 운영 entity master와 실제 운영 데이터 연결은 별도 작업 전까지 보류한다. 기술 구현 완료와 운영 활성화 가능성을 같은 상태로 표시하지 않는다.

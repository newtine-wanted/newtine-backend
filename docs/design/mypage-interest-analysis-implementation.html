현재 구현 (as-built)

승인된 읽기 경계를 구현했다. InterestController는 JwtAuthGuard와 인증 주체를 사용해 두 GET을 제공하고, InterestService는 서버 설정의 7일 rolling window·표본 상태·커서 해석을 조립한다. MikroOrmInterestRepository는 MikroORM QueryBuilder의 distinctOn으로 이슈별 최신 행동을 읽고 EntityManager의 find로 공개 이슈·분류를 조회한 뒤 PUBLISHED·LIKE만 집계하고 keyset 페이지를 만든다. 이벤트 쓰기 endpoint·UNLIKE·물리 삭제는 구현하지 않았다.

영향 경계: apps/api/src/interest/, apps/api/src/api.module.ts, libs/core/src/interest/, libs/core/src/core.module.ts, libs/core/src/common/database/database.options.ts, libs/core/src/index.ts, test/unit/, test/integration/databaseOptions.test.ts, Nestia generated contract.

검증 공백

  • 실제 DB migration과 ORM QueryBuilder 실행·EXPLAIN·동시 변경 경계는 disposable PostgreSQL 부재로 미검증이다.
  • 현재 목록 페이지의 정렬·sentinel 계산은 ORM으로 읽은 현재 관심 집합을 애플리케이션에서 수행한다. 사용자별 관심 이벤트가 대규모로 늘면 DB-side pagination 최적화를 별도 검토한다.
  • 이슈 상세 썸네일 필드가 없어 초기 응답은 null이며 화면의 optional 썸네일은 미제공으로 남는다.
  • 쓰기 endpoint를 보류했으므로 HTTP로 이벤트를 생성하는 end-to-end는 이 범위의 완료 기준이 아니다.

설계 delta

승인 기준선의 최근 7일·두 GET·10개 분류·G2 보류를 유지한다. as-built가 이 범위를 바꾸면 이 문서에 이유와 영향을 기록하고 설계 문서를 재승인 상태로 돌린다.

리뷰 유형: 수정 후 자기 변경 · 2026-09-15 KST · working tree와 HEAD 비교. 요청된 ORM 사용 여부, SQL 경계, 동작 정합성, 검증 공백을 점검했다.

리뷰 finding
ID·상태 근거 기대·실제 영향·다음 조치
REV-001 · 해결됨 libs/core/src/interest/mikroOrmInterest.repository.ts 기존 직접 EntityManager.getConnection().execute CTE를 제거하고 MikroORM QueryBuilder distinctOn과 EntityManager find로 최신 행동·이슈·분류를 조회한다. 애플리케이션 adapter에는 쌩쿼리가 없다. ORM metadata와 생성된 SQL을 한 경로로 관리한다. migration의 addSql은 스키마 DDL을 선언하는 MikroORM migration API이므로 조회 쿼리와 구분한다.
REV-002 · non-blocking risk Docker daemon 접근 권한 오류로 실제 PostgreSQL을 기동하지 못함. unit·integration·contracts는 통과. migration·최신 행동 QueryBuilder·keyset 경계의 실제 DB 실행 증거가 없다. 배포 전 disposable PostgreSQL에서 migration, 0/1/20/21건, 동률 cursor, WITHDRAWN, 동시 변경을 실행하고 EXPLAIN을 확인한다.
REV-003 · accepted 승인 기준선의 G2에 기록된 범위 관심 등록·해제 write endpoint는 아직 없다. 이번 읽기 API 승인 범위에서는 의도적 보류다. 이벤트가 생성되는 실제 HTTP 흐름을 완성하려면 별도 설계 재승인이 필요하다.
REV-004 · non-blocking risk MikroOrmInterestRepository.getLikedIssues 현재 관심 집합을 ORM으로 읽은 뒤 애플리케이션에서 total·정렬·sentinel을 계산한다. 계약과 keyset 정합성은 유지하지만 회원별 이벤트가 대규모로 늘면 DB-side pagination을 별도 최적화한다. 현재 승인 범위에서는 동작·ORM 전환을 우선한다.

리뷰 판단: 차단 결함 없음. 관심 조회 adapter의 직접 SQL 실행을 제거하고 ORM QueryBuilder/entity API로 교체했다. 남은 검증 공백은 Docker 권한 때문에 실제 PostgreSQL을 기동하지 못한 환경 이슈이며, migration의 DDL addSql은 의도된 schema migration 경계다.

최종 상태

운영 제어 보류. 승인 범위의 기술 구현은 완료했고, 구현 이해 점검은 미실시이며 live PostgreSQL과 범위 외 batch gate가 남아 있다. 보류된 쓰기·해제 정책을 추가하려면 설계 재승인 후 별도 구현 제어를 시작한다.

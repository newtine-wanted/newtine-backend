기준선과 승인 범위

PENDING·SKIPPED·COMPLETED의 complete 요청을 full replacement로 처리하고, category는 알려진 action contribution을 보존한 채 onboarding base를 재구성한다. 별도 snapshot table은 추가하지 않는다. topic/entity 응답은 aggregate에서 derived하며 residual anomaly는 내부 오류와 rollback으로 처리한다.

현재 구현

  • postgresOnboarding.repository.ts: PostgreSQL topic 정렬을 issue_categories.display_order로 통일했다.
  • inMemoryOnboarding.repository.ts: topic catalog order와 region code order를 production과 맞췄다.
  • OnboardingException.diagnostic 및 global exception filter로 user/category/ aggregate/action/residual을 내부 로그에 보존한다.

REV-002 열림 · P2 동일 payload 재전송 전용 회귀 테스트는 후속 보강 대상으로 남겼다. 현재 delete/reinsert 구현의 누적 결함은 관찰되지 않았다.
REV-003 해결됨 production/InMemory의 topic·region 순서와 회귀 테스트를 정렬했다. 없음. 배열을 set으로 소비하는 client에도 안정된 순서를 제공한다.
REV-004 해결됨 anomaly를 generic 500으로만 남기지 않고 structured log context를 추가했다. metric/alert 연결은 운영 설정 단계에서 별도 확인한다.
REV-005 해당 없음 정상 writer에서 발생하지 않는 stale timestamp 전제를 철회했다. legacy 데이터 점검을 별도 운영 범위로 잡을 때만 확인한다.

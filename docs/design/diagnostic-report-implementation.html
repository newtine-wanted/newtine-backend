검증 근거

  • 전체 단위 테스트: 39 suites / 191 tests 통과. 추천 철회와 사용량 회복 보완 회귀를 포함한다.
  • 전체 API·batch 빌드, 타입 검사, 포맷 검사 통과.
  • SDK·E2E 함수·OpenAPI 생성 및 계약 테스트 5개, 생성 코드 타입 검사 통과.
  • 빈 전용 PostgreSQL에 초기 스키마와 14개 마이그레이션 적용 성공.
  • 실제 JWT 인증, strict 요청, 타 회원 404, 202/200 재신청, 성공 재시도 금지 HTTP 테스트 통과.
  • 실제 worker 부팅·1회 큐 확인·종료 성공. 외부 fetch를 차단하여 사용자 입력 전송 없음.
  • 신규 격리 Docker Compose에서 db·migrate·api·report-worker를 실제 기동. 테스트 사용자와 공개 이슈·LIKE 4건을 주입한 뒤 POST 신청 → QUEUED → worker claim → GET SUCCEEDED/INSUFFICIENT_DATA를 확인했고, 같은 주간 재신청은 동일 reportId를 반환했다. 이 fixture는 AI 호출 조건 미충족으로 외부 요청과 usage ledger 기록이 0건이었다.

실제 PostgreSQL 전체 통합 5 suites / 18 tests 통과. 리뷰 수정 후 lifecycle·usage 6개 및 추가 terminal usage 복구 검증 통과. Docker Compose 격리 acceptance 흐름과 최종 lint·typecheck·build·format·diff 검사 통과. 두 차례 독립 리뷰의 소스 hash 불변 확인.

운영 순서

  1. ACT-01 관심 이벤트 쓰기와 이슈 상세·공유 임베딩 적재가 연결됐는지 확인한다.
  2. 기존 초기 스키마 확인 후 npm run db:migrate를 적용한다.
  3. 워커에 DB 설정, REPORT_AI_MODEL, OPENAI_API_KEY를 설정한다. 이 설정은 API나 기존 다른 배치에 요구되지 않는다.
  4. node dist/apps/batch/src/main.js reportWorker 또는 compose의 reports profile로 별도 실행한다.
  5. 회원 신청 후 status를 조회한다. 5개 미만은 INSUFFICIENT_DATA 성공 안내, FAILED는 nextRetryAt·retryable에 따라 안내한다.

기본값: poll 1초, 공급자 60초, lease 180초, heartbeat 30초, 전체 실행 5분. 장애 시 lease 회수와 attempt 이력을 확인한다. 성공 결과는 재생성하지 않는다.

검증 공백

실제 유료 AI 호출·설명 품질 및 모델별 컨텍스트 한계, 운영 배포는 수행하지 않았다. 공급자 HTTP 모의 응답과 실제 DB로 코드 경로를 검증했다. ACT-01 통합 후 실제 사용자 관심 입력 연계 검증이 필요하다.

잔여 위험

공급자가 요청을 처리했으나 응답이 유실되면 재시도에서 중복 과금될 수 있다. 이를 성공 0원으로 기록하지 않고 UNKNOWN·비용 NULL로 남긴다. 정확한 비용은 공급자 측 데이터로 정산해야 한다. 큰 이슈 코퍼스의 exact pgvector 검색 성능은 운영 규모 부하 검증이 필요하다.

설계 차이

승인한 사용자 동작과 데이터 계약의 변경 없음. 실제 SQL 실행 방식, 공개 이슈 잠금, 제한된 추천 후보 조회는 기존 불변 조건을 지키기 위한 구현 선택이다.

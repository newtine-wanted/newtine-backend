NestJS 기본 틀 구현 제어

승인된 설계의 as-built 상태와 검증 증거를 기록한다.

기준 설계

nestjs-foundation-design.html의 설계 승인됨 상태를 기준으로 한다. G1-A부터 G11-A, G10-S-A를 포함한 초기 실행 골격만 구현한다.

Goal
api, batch, core의 Nest CLI 모노레포와 MikroORM/PostgreSQL 기반 경계를 빌드·실행 가능한 상태로 만든다.
Scope
루트 설정, apps/api, apps/batch, libs/core의 포트·어댑터·transaction·예외 경계, health와 databaseCheck, 검증 설정.
Forbidden
실제 19개 테이블 업무 구현, 운영 데이터 변경, schema 자동 동기화, 큐·스케줄러·자동 재시도, 승인 없는 계약 변경.

현재 구현(as-built)

루트 package.json, package-lock.json, Nest CLI workspace, TypeScript·ESLint·Prettier 설정을 추가했다. ESM 프로젝트의 Nest 12 빌드는 webpack 대신 Rspack 2.2.3을 사용한다.

  • core: feature-first 업무 경계(issue/domain·issue/repository와 article/domain·article/repository), 여러 feature가 공유하는 common 기반 타입과 UUIDv7 ID 생성기, HTTP 독립 추상 DomainException과 도메인별 IssueException·코드, TransactionManager 계약과 MikroORM adapter(중첩 호출 거부 포함), PostgreSQL 옵션 및 CoreModule.
  • api: 서버 생성 요청 UUID middleware, RFC 9457 GlobalExceptionFilter, Nestia·Typia 입력 검증, 단순 health controller, CoreModule 조립. 도메인 예외는 API 정의로 매핑하고, 처리된 오류 로그에는 exceptionName·domain·domainCode·apiCode·requestId를 남긴다.
  • batch: 명시적 databaseCheck 작업, 작업별 RequestContext, 성공 0·실패 1 반환, application context finally 종료.
  • test: BatchRunner·TransactionManager·ProblemDetails 단위 테스트, database options 계약 테스트, API health/404 smoke script.

실제 업무 entity·VO·repository 구현은 승인 범위 밖이라 빈 scaffold로 남겼다.

구현 상태

현재: 운영 제어 보류. 승인 범위의 기술 구현과 집중 검증은 완료했지만 PostgreSQL 연결 성공 경로와 실제 업무 repository는 후속 범위이며, 개발자 운영 이해 점검은 미실시다.

승인 계약
경계 불변식 검증 결과

설계 delta

Rspack 빌더 추가는 ESM 프로젝트에서 Nest 12 빌드를 가능하게 하는 도구 설정 보정으로, API 계약·상태·실패 처리 변경은 없다. build는 api와 batch를 순서대로 빌드하고 deleteOutDir: false로 한 앱이 다른 앱 산출물을 지우지 않게 했다. MikroORM v7의 no-entity 기본 검증을 명시적으로 비활성화하고 ensureDatabase: false를 설정한 것은 업무 schema 자동 변경을 막기 위한 승인 범위 내 구체화다. 그 외 material delta 없음.

검증 증거

Node v24.18.0, npm 11.16.0 확인. 의존성 설치 후 다음 명령이 통과했다.

npm run format:check
npm run lint
npm run typecheck
npm run build:api
npm run build:batch
npm test
npm run test:unit
npm run test:integration
npm run test:smoke

위 명령의 실제 결과는 아래에 기록했다. DB가 없는 환경에서는 PostgreSQL 성공 경로와 commit/rollback 검증을 별도 공백으로 구분한다.

실제 결과: format·lint·typecheck·api build·batch build 및 전체 build 통과, npm test(단위 8건·integration 설정 테스트 1건) 통과, API smoke(health 200 및 RFC 9457 404) 통과. 전체 build 후 api와 batch 산출물이 모두 남는 것을 확인했다. Docker daemon socket은 샌드박스에서 접근 거부되어 PostgreSQL 성공 연결은 미실행이다. 로컬 PostgreSQL이 없는 상태에서 databaseCheck는 의도대로 오류 로그와 종료 코드 1을 반환했다. npm install은 5 high severity audit 항목을 보고했으며 자동 audit fix는 실행하지 않았다.

검증 공백

  • 격리된 PostgreSQL이 없어 실제 MikroORM 연결 성공과 transaction adapter의 DB commit/rollback은 미검증이다.
  • 실제 업무 entity·repository가 없으므로 다중 repository 원자성은 후속 범위다.
  • batch 업무의 멱등성·중복 실행 방지·재시도는 후속 업무 설계다.

잔여 위험

현재 Node/Nest/MikroORM 빌드 호환성과 HTTP·batch 골격은 확인했지만 PostgreSQL 성공 연결, 실제 ORM entity metadata, 다중 repository 원자성, 업무 batch 멱등성은 확인하지 않았다. npm audit가 보고한 5 high severity 항목도 의존성 업데이트 전에 영향 범위를 검토해야 한다.

코드 리뷰

유형: 자기 변경 리뷰. 기준 브랜치에는 커밋이 없어 비교 범위는 현재 신규 파일 전체다. 리뷰어는 구현 제어 기록을 바탕으로 입력·상태·부작용·관찰 경로를 읽기 전용으로 점검했다.

열린 finding
ID 상태·심각도 증거와 실제 동작 영향과 최소 조치
R-001 open · P1 libs/core/src/common/database/database.options.ts:7-11이 DB 사용자와 비밀번호를 postgres로 자동 대체한다. 설계 계약은 DB 자격증명을 환경변수로만 받는 것이다. 환경 누락이 조용히 공용 기본 자격증명 시도로 바뀐다. 비밀번호 fallback을 제거하고 필수 환경값을 기동 전에 검증하며, 개발 기본값이 필요하면 명시적인 development 전용 설정으로 제한한다.
R-002 fixed · P1 libs/core/src/common/transaction/mikroOrm/mikroOrm.transactionManager.ts:11-18가 isInTransaction()을 확인하고 중첩 호출에서 NestedTransactionException을 반환한다. 승인 계약의 중첩 트랜잭션 명시적 거부로 동작이 맞춰졌다. savepoint를 열지 않고 내부 work도 실행하지 않는 단위 테스트가 통과했다.
R-003 open · P2 apps/api/src/main.ts:8-23은 app.listen() 실패를 catch/finally로 감싸지 않는다. API_PORT=invalid node dist/apps/api/main.js는 앱 초기화 로그 뒤 ERR_SOCKET_BAD_PORT의 처리되지 않은 예외로 종료됐다. 포트 충돌·잘못된 설정·후속 모듈 초기화 실패에서 graceful close와 통제된 실패 로그가 보장되지 않는다. app 참조를 유지하고 catch에서 오류를 기록한 뒤 finally에서 app.close(), 실패 시 process.exitCode = 1을 설정한다.

위 finding 외에 승인 범위 안의 코드·타입·빌드·HTTP smoke에서 추가 concrete finding은 확인하지 못했다. PostgreSQL 성공 연결과 실제 업무 entity/repository 원자성은 기존 검증 공백으로 남는다.

리뷰 검증 증거
  • npm run format:check, npm run lint, npm run typecheck 통과
  • npm run build 통과; API·batch 산출물 모두 생성
  • npm test 통과: 단위 8건, integration 1건
  • npm run test:smoke 통과: health 200, RFC 9457 404
  • 기준 커밋 없음: 현재 브랜치 main에 비교할 commit이 없다.

리뷰 판단: blocker 있음. R-001은 승인된 보안 계약을 직접 위반하고 R-003은 기동 실패 정리를 보장하지 않는다. R-002는 수정 및 회귀 검증으로 해결됐다.

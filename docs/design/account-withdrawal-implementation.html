승인 기준과 범위

이 문서는 승인된 설계의 구현 결과만 기록한다. 승인된 동작은 POST /auth/withdraw, JWT principal 본인 식별, 본문 없는 요청, 즉시 물리 삭제, 복구 없음, 개인 데이터와 모든 refresh session 삭제, 공유 콘텐츠 유지, 정상 응답 204다.

승인된 불변식은 회원 행 잠금 후 종속 데이터 처리, 삭제 후 access/refresh 인증 실패, 개인 보고서 결과 부활 금지, 외부 호출 중 DB 잠금 금지, 이미 허가된 외부 호출의 취소·과금 취소 미보장이다.

금지 범위는 유예·복구, 비밀번호 재확인, 관리자 강제 삭제, 운영 DB 실행, 외부 공급자 호출, PR·배포다. 구현 중 발견한 추가 개인 저장소나 계약 변경은 설계 문서 재승인 대상으로 전환한다.

현재 구현

구현 완료. codex/account-withdrawal 워크트리의 단일 구현 lane에서 승인된 execution contract를 반영했다. AuthController.withdraw와 WithdrawUseCase는 principal.userId만 사용하고, users 행을 먼저 잠근 뒤 CASCADE 물리 삭제를 한 트랜잭션으로 수행한다.

auth.controller.ts의 새 route와 withdraw.usecase.ts, postgresAuth.repository.ts의 user-first delete, account-withdrawal migration의 FK preflight·보완, report/usage/feed 경합 경계를 함께 반영했다. OpenAPI·SDK·E2E 생성물과 회귀 테스트도 갱신했다.

운영 적용은 보류한다. 실제 격리 PostgreSQL에서 migration·삭제 범위·rollback·동시성 HTTP 검증을 아직 실행하지 않았고, migration을 운영 DB에 적용하지 않았다.

이슈 등록부

구현 이슈와 조치
상태 증상·영향 원인·조치 검증·잔여 위험
해결 · P0 탈퇴 트랜잭션의 두 SET LOCAL을 한 드라이버 호출로 보내면 PostgreSQL 다중 결과 해석 오류로 500·rollback 가능. SET LOCAL lock_timeout과 statement_timeout을 단일 statement별 호출로 분리했다. PostgresAuthRepository 회귀 테스트 4개 호출 순서 확인; 실제 DB는 미실행.
해결 · P2 / 호환 명시 parser가 소비하지 않은 non-empty text/plain·chunked 본문이 undefined로 남아 탈퇴를 우회할 수 있음. JSON {}는 승인 설계의 호환용 빈 객체다. positive content-length는 즉시 거절하고, chunked 요청은 실제 스트림 바이트를 확인해 non-empty만 400으로 거절한다. 파싱된 빈 객체는 필드가 없을 때 호환 허용하고, 필드가 있으면 400이다. request boundary unit에 non-empty text/plain·empty/non-empty chunked 경계를 추가; 실제 HTTP는 미실행. strict zero-byte-only로 바꾸려면 설계 재승인이 필요하다.
해결 · SCHEMA 외부 소유 base schema의 개인 FK가 다르면 users DELETE 범위가 불명확함. 전체 inbound users FK를 명시적 table/column/action allowlist와 대조하고, known member-owned tables의 validated ON DELETE CASCADE와 ai_usage weekly_report_id SET NULL을 preflight에서 확인한다. 불일치·예상 밖 FK·고아 데이터는 fail-closed한다. migration SQL static/unit 확인; 실제 운영 schema introspection은 배포 전 필수.
열림 · ENV-001 격리 PostgreSQL lifecycle/HTTP/경합 suite를 실행할 REPORT_TEST_DATABASE_URL과 접근 가능한 local PostgreSQL이 없음. unit·static·생성 계약 검증까지 수행하고, DB 검증은 운영 적용 전 gate로 남겼다. DB URL 제공 후 migration·withdrawal integration suite를 실행해야 한다.
열림 · OPS-001 탈퇴 commit과 이미 허가된 외부 AI 전송 사이 race, 로그·백업·provider 보존. 승인 설계의 비범위로 유지하고 운영·공급자별 별도 정책으로 분리했다. 204를 외부 사본 즉시 삭제·과금 취소로 설명하지 않는다.

검증 공백과 잔여 위험

남은 공백은 구현 실패가 아니라 환경·운영 gate다. REPORT_TEST_DATABASE_URL을 연결한 격리 PostgreSQL에서 migration up, users 삭제와 모든 개인 행/guest 행 보존, 실패 rollback, login·refresh·feed·report·usage·worker 양방향 경합, late provider 결과를 실행해야 한다. migration 적용 전에는 API를 배포하지 않는다. 호출 허가 commit과 provider 전송 사이 race, 이미 guard를 지난 요청, 기존 로그·백업·외부 provider 보존은 승인 설계의 잔여 위험이다.

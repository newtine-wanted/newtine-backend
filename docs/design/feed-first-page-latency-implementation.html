1. 승인된 설계와 실제 결과

설계 기준은 첫 피드 조회 지연 개선 설계와 실행 계약이다. 구현 중 새 API·DB schema·lock·pool·운영 로그 정책을 추가하지 않았다.

운영 판정: v2 활성화·배포 승인이 아니다. 새 세션의 기본은 계속 v1이며, p95와 전체 HTTP smoke 증거가 생긴 뒤 별도 운영 판단이 필요하다.

2. 실제 실행 흐름과 상태 경계

candidate query는 ID만 읽어 identity map에 부분 issue entity를 남기지 않는다. feed mode는 카드에 필요한 summary·impact·entity를 유지하지만 기사 링크·article·publisher entity는 hydrate하지 않고 개수를 별도 집계한다. detail mode의 기사 순서와 publisher fallback은 기존 경로를 유지한다.

7. 잔여 운영 위험과 다음 행동

  1. 배포 전 disposable PostgreSQL에서 candidate projection → feed/detail count equivalence → same EntityManager detail reload를 자동 smoke로 추가한다.
  2. v2를 활성화하기 전에 새 세션 기준 cold/warm, 회원/게스트, 이력 규모, 동시성별 첫 HTTP p50/p95/p99를 직접 측정한다. 500ms 목표 미달이면 이 구현을 성공으로 포장하지 않는다.
  3. v2 세션 TTL 동안 v2 코드를 유지하고, 운영 rollback은 신규 생성 버전만 v1로 바꾼다. 실제 설정·배포는 별도 승인이다.
현재 작업 상태: 구현은 이 worktree에만 있고 commit/PR/push/deploy하지 않았다. 기본 환경값은 v1이므로 운영에서 v2가 자동 활성화되지 않는다.

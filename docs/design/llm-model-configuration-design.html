LLM 모델 설정 경로 개선

목적
파이프라인과 진단보고서의 텍스트 LLM 모델을 환경변수 우선으로 선택하고, 미설정 시 현재 모델을 안전한 기본값으로 사용한다.
사용자
NEWTINE 백엔드 개발자와 batch 운영자
문제
파이프라인 모델은 config/pipeline-ai.yml에 고정되어 있고 보고서 모델은 REPORT_AI_MODEL이 비어 있으면 worker가 시작되지 않는다.
핵심 흐름
환경변수 읽기·정규화 → 설정 파일 또는 기본 모델 fallback → OpenAI 요청 payload → 사용량 원장
추적
현재 대화의 “env 값 기준, 없으면 기존 모델 fallback” 요청을 위한 후속 설계. 기존 콘텐츠 파이프라인 설계 문서는 더 넓은 목적의 기준선이므로 이 설정 목적의 동료 문서를 사용한다.
목표구조의사결정실패·복구검증이해 점검승인

1. 목표·범위

  • 환경변수에 공백이 아닌 모델명이 있으면 실제 OpenAI 요청에 그 값을 사용한다.
  • 환경변수가 없거나 빈 값이면 현재 모델 gpt-5.4-mini-2026-03-17을 기본값으로 사용한다.
  • 보고서 worker가 모델 미설정만으로 실패하지 않도록 하되, OPENAI_API_KEY 필수 조건은 유지한다.
  • 프롬프트·JSON schema·embedding 모델·API 요청 계약은 범위 밖으로 둔다.
현재 근거: 파이프라인 text stage는 YAML의 model을 payload에 넣고, 보고서는 REPORT_AI_MODEL을 필수로 읽는다. pipeline.worker.ts의 hardcoded 모델은 주로 사용량 기록 fallback이므로 실제 호출 설정과 분리해 다뤄야 한다.

3. 설계 의사결정 · grilling 완료

결정 반영: 사용자는 권고안대로 G1-B·G2-A를 선택했다. material frontier는 닫혔으며, 아래 결정은 구현 승인과 별개인 설계 기준선이다.

확정된 설계 결정
ID결정확인된 근거·선택지권고와 트레이드오프
G1 환경변수 우선 적용 범위 A: 보고서의 REPORT_AI_MODEL만 fallback 처리한다.
B: pipeline text와 report를 각각 PIPELINE_AI_MODEL·REPORT_AI_MODEL로 제어한다.
C: 하나의 공통 OPENAI_MODEL로 두 경로를 묶는다.		 G1-B 확정 — 운영 환경별 독립 rollout을 유지하면서 두 경로 모두 env-first가 된다. C는 보고서와 뉴스 파이프라인의 변경을 불필요하게 결합하고, A는 pipeline의 기존 고정 설정 문제를 남긴다.
G2 Pipeline env가 없을 때의 우선순위 A: stage YAML 모델을 유지하고, YAML까지 비면 공통 기본값을 사용한다.
B: env가 없으면 YAML 모델을 무시하고 곧바로 공통 기본값을 사용한다.		 G2-A 확정 — 현재 stage별 모델 설정과 향후 stage별 분리를 보존하면서, 설정 파일 누락에도 안전한 fallback을 추가한다. 공통 env가 있으면 모든 text stage에 우선 적용한다.

공통 기본값: gpt-5.4-mini-2026-03-17. 공백 문자열은 미설정으로 취급하고, 임의의 비공백 모델명은 그대로 전달하여 공급자 검증 결과를 보존한다.

4. 불변식·비범위

  • 실제 provider payload의 model과 성공·실패 사용량 기록의 모델은 동일한 resolved model을 기준으로 한다.
  • 환경변수 값이 유효한 비공백 문자열이면 hardcoded 기본값이 이를 덮어쓰지 않는다.
  • OPENAI_API_KEY 누락은 모델 fallback으로 완화하지 않는다.
  • embedding 모델과 REPORT_AI_MODEL·PIPELINE_AI_MODEL의 의미를 혼용하지 않는다.
  • API request body에 model 필드를 추가하지 않는다. 모델은 worker 운영 설정으로만 결정한다.

5. 최종 설계 요약

공통 기본값
gpt-5.4-mini-2026-03-17을 코드의 단일 기본값으로 둔다.
Pipeline text
PIPELINE_AI_MODEL이 비어 있지 않으면 candidate·content·validation 모두에 적용한다. 없으면 각 stage YAML의 모델을 사용하고, YAML 모델도 없으면 공통 기본값을 사용한다.
Report text
REPORT_AI_MODEL이 비어 있지 않으면 사용하고, 없으면 공통 기본값을 사용한다. 모델이 없다는 이유로 report worker를 실패시키지 않는다.
Embedding
text-embedding-3-small과 현재 embedding 설정 경계는 유지한다. 이번 변경에서 text LLM 환경변수와 혼용하지 않는다.
Credentials
OPENAI_API_KEY 검증과 외부 호출 실패 분류는 변경하지 않는다.

7. 검증 계획

  1. report: env 모델 사용, env 미설정·빈 문자열 fallback, API key 검증 유지.
  2. pipeline: PIPELINE_AI_MODEL override, env 미설정 시 YAML 모델, YAML model 누락 시 공통 fallback.
  3. provider payload: resolved model이 실제 request body와 usage metadata에 반영되는지 확인.
  4. focused command: npm run test:jest -- test/unit/reportOptions.test.ts test/unit/pipelineAiConfiguration.test.ts test/unit/openAiProvider.test.ts test/unit/reportProvider.test.ts
  5. applicable gates: npm run format:check, npm run lint, npm run typecheck, npm run build

10. Execution Contract · 승인됨

Goal
pipeline text와 report text 모델을 env-first로 resolve하고, 미설정 시 gpt-5.4-mini-2026-03-17을 사용한다.
Observed evidence
pipeline stage 모델은 config/pipeline-ai.yml에서 읽고, report 모델은 REPORT_AI_MODEL을 필수로 읽는다. 현재 .env의 report 모델 값은 비어 있다.
Files and symbols in scope
apps/batch/src/ai/ai-model.defaults.ts(신규), apps/batch/src/pipeline/pipeline.ai.config.ts, apps/batch/src/pipeline/pipeline.worker.ts, apps/batch/src/report/report.ai.config.ts, 관련 4개 unit test, .env.example, compose.yaml, README.md. 구현 제어 기록은 동료 문서에서 관리한다.
Invariants
env non-empty override, pipeline env→YAML→default precedence, report env→default precedence, embedding 분리, API key 검증 유지, resolved model과 provider payload·usage metadata 정합성.
Implementation steps
공통 default 상수 추가 → pipeline/report resolver 수정 → usage fallback 정합화 → env 예시·Compose·README 갱신 → focused regression test 추가 → typecheck/build/lint/format 검증.
Acceptance criteria
네 가지 precedence/fallback 경우와 blank env가 테스트되고, provider request body에 resolved model이 들어가며, report model 미설정만으로 worker가 실패하지 않는다.
Verification commands
npm run test:jest -- test/unit/reportOptions.test.ts test/unit/pipelineAiConfiguration.test.ts test/unit/openAiProvider.test.ts test/unit/reportProvider.test.ts, 이후 npm run format:check, npm run lint, npm run typecheck, npm run build
Forbidden changes
API body에 model 추가, embedding 모델 정책 변경, DB migration, 실제 OpenAI 호출, 사용자 .env 값 변경, unrelated generated artifacts 수정.
Escalate when
stage별 env를 별도로 둘 필요가 생기거나, embedding도 env-first로 바꾸거나, report·pipeline을 하나의 모델 env로 묶어야 한다는 요구가 추가될 때.

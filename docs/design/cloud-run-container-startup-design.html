목적
Cloud Run revision이 플랫폼이 지정한 HTTP 포트에서 정상적으로 수신하도록 API bootstrap 계약을 고정한다.

런타임 계약

현재 문제와 승인된 변경
항목승인된 계약
포트PORT → API_PORT → 3000 순서로 해석한다.
호스트API_HOST가 있으면 유지하고, 없으면 0.0.0.0에 바인딩한다.
로컬 개발.env의 명시적 API_HOST=127.0.0.1은 그대로 존중한다.
비목표Cloud Run 배포 실행, 환경변수 삭제, 라우트·DB·인증 계약 변경은 수행하지 않는다.
 
const port = Number(process.env.PORT ?? process.env.API_PORT ?? 3000);
await app.listen(port, process.env.API_HOST ?? '0.0.0.0');

핵심 위험과 불변식

위험: Cloud Run은 컨테이너 외부의 ingress 경로로 접속하므로 127.0.0.1만 수신하면 startup 확인이 실패한다.

불변식: 플랫폼의 PORT를 우선하고, Cloud Run 기본 바인딩은 0.0.0.0이어야 한다. 명시적인 로컬 API_HOST는 덮어쓰지 않는다.

검증 계획

  1. 변경 diff가 apps/api/src/main.ts의 승인 범위 안에 있는지 확인한다.
  2. npm run format:check, npm run lint, npm run typecheck, npm run build:api를 실행한다.
  3. Cloud Run 재배포는 사용자가 별도로 실행하며, 실패 시 revision 로그에서 startup 전 애플리케이션 종료와 포트 미수신을 구분한다.

설계 이해·통제 점검

상태: 미실시. 이 점검은 구현 승인과 별개이며, 브라우저의 결과는 Codex에 자동 전달되지 않는다.

적용 범위 축: 목표·범위, 호스트/포트 불변식, 로컬/Cloud Run 경계, 실패 진단, 검증. 외부 배포 변경은 이번 작업에서 실행하지 않으므로 해당 없음으로 기록한다.

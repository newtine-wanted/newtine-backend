현재 구현(as-built)

승인 기준선의 API·추천 규칙·상태 경계와 후속 리뷰 개선을 구현했다. PostgreSQL 계약 정합성, 공개 기사 상태 predicate, transaction/만료 경계, 이전 batch bulk-load, InMemory scope parity, production ORM provider 경계를 반영했다. 기존 검색 계약과 인증·사용자 정보 경계는 보존한다.

  • FeedController: POST /feed-sessions와 POST /feed-sessions/:sessionId/batches.
  • IssueController: GET /issues/:issueId 상세와 기존 POST /issues/search.
  • issueRecommendation.ts: 7항목 가중합, 4/2/1/2/1 배정, 후속·중복·연속 제한·예산 상태. 대체 후보는 candidate budget 전체를 스캔하되 최대 3 rounds·후보당 2개 replacement proposal로 bounded search한다. 이 상한으로 미입증된 불완전 결과는 SEARCH_LIMITED로 분류한다.
  • 후보 예산은 RECOMMENDATION_CANDIDATE_BUDGET(10~500, 기본 100), 높은 점수 기준은 RECOMMENDATION_HIGH_SCORE_THRESHOLD(0~1, 기본 0.7)로 제한한다. 운영 기본값은 외부 점수 계약 확인 전 최종 정책이 아니다.
  • 테스트 전용 InMemory adapter와 passthrough transaction fixture를 test/fixtures로 이동하고, production에는 IssueCardQueryRepository 하나만 등록했다. 이슈·상세·기사·관계·feed 상태 EntitySchema를 database options에 등록하고, feed/read-model migration은 schema evolution 책임으로 유지한다.
  • 게스트 세션은 서버가 발급한 고엔트로피 bearer key를 생성 응답으로 한 번 전달하고, 저장소에는 SHA-256 해시만 남긴다. 배치 요청은 해당 key를 소유 증명으로 보내며, 최초 생성 멱등 키는 구현하지 않았다.
  • x-user-id는 인증 분기 연결 전 임시 principal 경계이므로 운영에서 직접 신뢰하지 않고 검증된 인증 principal로 교체해야 한다.
  • 상세의 관점·용어 JSON article reference는 현재 이슈의 연결 기사에 없는 ID를 제거한다.
  • 제한 상태 이후 새 batch는 서비스와 저장소 transaction에서 모두 거절하며, 같은 batch 재시도는 저장된 묶음을 복원한다.
  • batch 계산은 use case의 TransactionManager 경계에서 후보 조회부터 저장까지 수행한다. PostgreSQL adapter는 ambient transaction만 사용하고, 저장 직전 잠금 후 ORM criteria에서 database clock으로 세션 만료를 재확인한다.
  • 이전 batch item은 한 번에 bulk-load한다. test fixture adapter도 personalized/major/ connected/exploration/mismatch slice, 제외 ID, limit, global fill semantics를 production ORM adapter와 맞춘다.
  • 공개 기사·개수·reference는 source_status = 'AVAILABLE'만 사용한다. 현재 producer가 main topic·대표 대상을 쓰지 않으므로 PostgreSQL capability는 명시적으로 비활성이고 임의 대체값을 만들지 않는다.

구현 이해·통제 점검

상태: 기술 구현·로컬 게이트 및 Compose DB smoke 완료, 운영 제어 보류. 후속 G24~G27·G28~G31 및 CQ-REV-011 보완은 승인된 범위로 반영했지만, 실제 업무 PostgreSQL lock/EXPLAIN/p95·인증 principal·온보딩 지역/나이대·점수/대표 대상 producer 계약에 대한 운영 이해 점검은 아직 실시하지 않았다. 운영 연결 전에 요청 소유권, 같은 묶음 재시도/동시성, 24시간 만료 race, 후보 탐색 상한과 빈 피드 구분, AVAILABLE 기사 정책을 담당자가 설명하고 격리 환경 증거로 재검증해야 한다. 이 점검은 기술 완료나 설계 승인과 별개다.

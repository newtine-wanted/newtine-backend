구현 모델

  1. 공통 `createLoggerOptions(service)`에서 level, service, redaction, 개발 transport를 만든다. `LOG_LEVEL`과 `HTTP_SLOW_THRESHOLD_MS`의 허용값을 시작 시 검증한다.
  2. API·batch 모듈은 `LoggerModule.forRoot()`를 한 번만 등록하고 main에서 `app.useLogger()`로 Nest 로그를 교체한다.
  3. Pino HTTP middleware의 `genReqId`는 입력 request 값을 신뢰하지 않고 UUIDv7을 생성한다. `HttpRequestContextMiddleware`는 이미 부여된 req.id를 requestId와 헤더에 연결하고, 직접 middleware 경로에서는 자체 UUIDv7 fallback을 사용한다.
  4. `autoLogging: false`로 정상 HTTP 완료 로그를 끈다. 필터는 예외 진단을 한 번 기록하고, 별도 HTTP 응답 완료 hook이 느린 정상 요청만 warn으로 기록한다. 필터는 PinoLogger를 필수로 주입받으며 별도 fallback logger 경로를 두지 않는다.
  5. 5xx 진단은 `exceptionDiagnostic`을 통해 예외 message와 stack 첫 줄을 제외하고, cause의 이름·stack frame만 깊이 제한으로 기록한다. 알려진 password·token·authorization· query 패턴은 `[REDACTED]`로 보정해 Pino field redaction만으로 해결되지 않는 문자열 노출도 줄인다.
  6. batch는 `PinoLogger.runInContext` 공개 API를 사용해 jobName·executionId를 묶고, 종료 시 app.close와 flush를 수행한다. `PinoLogger`가 transient라 API는 `resolve()`로 획득한다.
  7. 명시적 로그 작성자는 `GlobalExceptionFilter`, `HttpRequestContextMiddleware`, `BatchRunner`, bootstrap별 context를 설정해 동일 requestId·executionId 안에서 발생 지점을 구분한다.

검증 계획과 현재 공백

  • 정적: npm run typecheck, npm run lint, npm run format:check, npm run build 모두 통과.
  • 단위·통합: 26개 단위 테스트와 5개 통합 테스트 통과. logger option, threshold, filter object logging, batch context와 종료를 확인.
  • 실제 HTTP: npm run test:smoke 통과. 정상/4xx/413/404/parser 실패, UUIDv7 헤더와 로그 일치, body·parser sentinel 제외, JSON 줄과 requestId 중복 부재를 확인.
  • batch smoke: unknown job 실행에서 구조화된 batch.unknown_job 로그와 exit code 1, 정상 종료 경로의 app.close·flush를 확인.
  • 계약: npm run contracts:check 통과. SDK·e2e·OpenAPI 생성, RFC 9457 실패 응답 검사와 생성 TypeScript typecheck를 확인.
  • 전체 지연 메트릭의 수집기·조회까지는 이번 구현에서 완료하지 않는다. timer와 느린 요청 로그의 경계만 검증하며, 향후 histogram 수치·label·다중 인스턴스 집계를 별도 검증한다.
검증 결과 Pino/nestjs-pino의 실제 공개 API와 Nest 미들웨어 순서는 baseline과 일치했다. transient logger의 `resolve()` 예외만 구현 이슈로 기록하고 해결했다.

잔여 위험과 공백

  • 전체 지연 histogram과 수집·조회 경계는 2차 범위다. 현재 구현만으로 p95/p99나 다중 인스턴스 분포를 조회할 수 없다.
  • API 업무 이벤트의 표준 event 목록과 서비스별 기록 위치는 업무 기능 구현 때 확정한다.
  • npm install 당시 7개 취약점(중간 1개, 높음 6개)이 보고됐다. 의존성 경로 분석과 remediation은 이번 로깅 구현 범위에서 수행하지 않았다.

구현 이해 점검

상태: 미실시. 기술 검증은 완료됐으나 요청 격리·parser 오류·느린 요청 경계·redaction·batch 종료를 실제 as-built 기준으로 묻는 별도 점검은 아직 보고되지 않았다.

구현 제어 상태

운영 제어 보류. 기술 상태는 승인된 baseline 범위의 Pino 적용, 요청·배치 컨텍스트, 예외·느린 요청 로그 구현과 정적·테스트·실행·계약 검증 완료다. 메트릭 수집·조회와 비즈니스 이벤트 표준은 보류 범위다.

잔여 제어: 구현 이해 점검은 미실시다. 이 상태는 기술 검증을 되돌리지 않으며, 운영 인수 전에 요청 ID 상관관계·예외 중복 억제·slow threshold·batch 종료와 보류된 메트릭 범위를 실제 as-built 기준으로 확인한다.

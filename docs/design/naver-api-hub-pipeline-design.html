목표와 범위

API HUB 검색 계약 적용, 응답 정규화, 직접 입력할 빈 자격증명 설정과 운영 문서 준비. BIG KINDS·DeepSearch·RSS는 이번 공급자 추가에서 제외하고 열린국회정보는 후속 검토한다.

출처: 뉴스 api 기획, NAVER API HUB 공식 명세.

확인된 구조

apps/batch/src/pipeline/naverNews.provider.ts는 openapi.naver.com 및 X-Naver-Client-* 헤더를 사용한다. API HUB는 https://naverapihub.apigw.ntruss.com/search/v1/news 및 X-NCP-APIGW-API-KEY-ID / X-NCP-APIGW-API-KEY를 사용한다.

현재 검색은 단일 query, start=1, sort=date. 제목/description 태그 제거와 원문 URL 우선 선택이 이미 있다. 본문 HTML 다운로드·추출이 별도 존재한다.

설계 의사결정 상태

완료 · G1-A를 사용자가 선택함. 검색 연동만 교체하며 본문 수집·생성·검증을 유지한다. 이 답변은 설계 선택이며 구현 승인은 아니다.

현재 frontier 없음. 검색 공급자는 새 API HUB 하나로 전환한다. 기존 환경변수 이름을 유지하여 배포 설정 변경을 줄이고, 값은 API HUB에서 발급한 Client ID/Secret을 넣도록 문서화한다. 구 개발자센터 키 자동 fallback은 제공하지 않는다.

기각한 대안: description만으로 생성하는 방식은 기존 본문 근거 계약을 바꾸므로 이번 범위에서 제외. 복수 뉴스 공급자 및 열린국회정보 연동은 후속 검토.

불변 조건과 외부 효과

키/시크릿은 값 없이 설정 자리만 제공한다. 실제 API 호출·자격증명 발급·배포는 하지 않는다. description을 본문으로 위장하거나 기존 근거 검증을 묵시적으로 완화하지 않는다. 공개 원자성과 실행 중복 방지 유지가 기본 제약이다.

실패와 복구

현재 오류 분류를 유지한다. 미설정/빈 키는 외부 호출 전에 실패한다. 429/5xx 및 네트워크 오류는 기존 파이프라인 재시도 정책을 따르고, 그 외 HTTP 실패는 SourceUnavailable로 분류한다. JSON 파싱·구조 오류는 InvalidOutput이다. 자동으로 구 API에 재요청하지 않는다.

본문 2개 미만이면 기존처럼 생성 전 실패한다. 실패는 기존 실행 조회와 오류 코드로 진단하고 설정 또는 공급자 문제를 해결한 후 기존 수동 재시도 절차를 따른다. 실제 키가 없으므로 인증 성공과 운영 쿼터는 실연동 검증에서 제외한다.

목표와 범위

검색 API의 메타데이터는 후보 발견과 중복·신규 분류에 사용하고, 실제 요약·근거 검증·연령대별 영향 분석은 외부 언론사 원문 본문을 입력으로 사용한다.

포함

유지

제외

시스템 모델과 변경 경계

현재 코드에는 이미 FetchedArticle.body, OpenAiContentGenerator, GeneratedIssueContent.impacts와 AGE_19_34 등 연령대 target이 있다. 변경의 중심은 NaverArticleBodyProvider가 Naver host만 허용하는 경계를 외부 원문 정책으로 바꾸는 것이다.

확인된 사실과 현재 불일치

로컬 코드·실행에서 확인된 경계
영역확인된 사실새 요구사항과의 관계
Naver 매핑sourceUrl은 originallink 우선, naverUrl은 link로 저장된다.본문 수집 대상은 Naver mirror가 아니라 원칙적으로 originallink다.
본문 providerNaverArticleBodyProvider는 현재 news.naver.com 계열 host만 허용하고 외부 host를 SOURCE_UNAVAILABLE로 거부한다.사용자 요구와 직접 충돌하는 변경 지점이다.
LLM 생성content stage가 본문 최대 18,000자를 OpenAI에 보내고 구조화 JSON을 받는다. summary, viewpoints, glossary, impacts를 생성한다.원문 본문만 확보되면 기존 구조가 요약·분류·연령대별 영향 출력에 사용될 수 있다.
검증·공개본문 2개 이상과 서로 겹치지 않는 독립 evidence group 2개를 요구한다.외부 원문 허용 때문에 이 검증 조건을 낮추면 안 된다.
보존migration 주석과 OpenAI store:false 경계상 body·prompt·raw response는 영구 저장하지 않는다.외부 원문 활용이 저장 정책을 암묵적으로 바꾸지 않도록 유지한다.

불변 조건과 안전 경계

  • 근거: Naver description은 본문으로 승격하지 않는다. 생성·검증 입력은 실제 추출된 FetchedArticle.body뿐이다.
  • URL 안전: http/https 외 scheme, 사용자정보, 비표준 port, private/link-local/loopback/reserved IP, 위험한 DNS 재해석, 허용되지 않은 redirect를 차단한다. 응답마다 content-type·최대 바이트·timeout을 검사한다.
  • 프롬프트 주입: 기사 본문 속 명령은 데이터로 취급하고 LLM 지시로 따르지 않는다. 출력은 strict schema와 서버 validator를 모두 통과해야 한다.
  • 공개: body 2개 미만, 독립 근거 부족, 구조·근거 검증 실패 시 생성·공개하지 않는다. 실패 job은 SOURCE_UNAVAILABLE 또는 INVALID_OUTPUT으로 남긴다.
  • 개인정보·저작권: body, prompt, provider raw response를 로그·DB·embedding 입력에 남기지 않는다. 외부 원문은 처리 목적과 보존 기간을 별도로 결정한다.
  • 분석 범위: 세대별 효용성은 입력 본문에 근거한 정책·영향 설명으로만 출력하며 개인의 정치 성향, 민감 속성, 성격을 추론하지 않는다.

설계 의사결정 상태 (grilling)

진행 상태: 완료

사용자가 모든 권고안을 선택했다. 아래 결정이 이번 구현의 승인된 설계 baseline이며, 선택하지 않은 branch는 별도 측정·승인 없이는 열지 않는다.

확정된 결정과 보류된 확장
결정확정 baseline보류·잔여 위험
G1 URLA — public internet의 http/https URL을 허용하되 scheme, userinfo, port, DNS/IP, redirect hop, timeout, response size, content-type을 매 단계 검증한다.publisher allowlist나 extraction service는 도입하지 않는다. SSRF·DNS rebinding·redirect 차단과 운영 지표가 필수다.
G2 추출A — 정적 HTML 우선 추출. JS-only, paywall, robots 차단, 비HTML, 본문 부족은 SOURCE_UNAVAILABLE로 종료한다.headless browser와 외부 extraction service는 실패 publisher 비율을 측정한 뒤 별도 설계한다.
G3 LLMA — 기존 categoryCode, summary, viewpoints, glossary, AGE_GROUP impacts와 articleIds 근거 계약을 재사용하고 prompt·validator를 강화한다. 이번 범위에는 숫자 효용성 점수·신뢰도 필드를 추가하지 않는다.정량 점수나 confidence가 제품 요구가 되면 API/DB/UI 계약을 새로 설계한다.
G4 보존A — 원문·prompt·provider raw response는 메모리 처리 후 폐기하며 DB, 로그, usage, embedding에 남기지 않는다. 재시도는 재수집한다.TTL cache와 영구 snapshot은 도입하지 않는다. 재수집 비용과 publisher 변동성이 운영 위험으로 남는다.

결정 기록: G1-A / G2-A / G3-A / G4-A. 이 변경은 단순 Naver allowlist 제거가 아니라 외부 효과·보안 경계·LLM 근거 계약을 함께 변경한다.

실패·복구·운영 초안

  1. URL parse·scheme·DNS/IP·redirect 검증 실패는 외부 원문 SOURCE_UNAVAILABLE로 기록하고 다음 후보로 진행한다.
  2. 429/5xx/network timeout은 기존 transient retry 한도 안에서 재시도하며, 결과 불명 호출은 usage에 실패/unknown으로 남긴다.
  3. JS-only, paywall, robots 차단, 비HTML, 본문 길이 부족은 본문 확보 실패로 분류한다. description으로 보정하지 않는다.
  4. LLM strict JSON·서버 shape·근거 reference·semantic validation 실패는 공개하지 않고 job 실패로 종료한다.
  5. 일부 후보만 성공하면 job별 결과와 run의 PARTIALLY_SUCCEEDED를 유지하되, 성공한 이슈만 공개한다.
외부 URL fetch를 추가하는 구현은 단순 allowlist 제거가 아니다. DNS 해석과 redirect를 매 hop 검증하고, 실제 publisher별 실패율·차단 사유·본문 길이·LLM 비용을 관찰할 수 있어야 한다.

검증 계획

  • provider unit: originallink 우선, naver link fallback, HTTPS/HTTP, private IP·localhost·userinfo·비표준 port·redirect chain·DNS failure·timeout·content-length/stream size·HTML content-type·본문 추출 실패를 검증한다.
  • LLM contract: 외부 본문이 content prompt에 들어가고, summary/viewpoint/glossary/AGE_GROUP impacts가 article ID를 참조하며, 본문 속 prompt injection과 invalid output이 공개를 막는지 검증한다.
  • pipeline integration: 실제 PostgreSQL에서 외부 URL 2개 이상 → OpenAI content/validation → issue_details, issue_impacts, issue_articles, embedding task와 terminal status를 확인한다.
  • negative live: 외부 publisher 일부 차단·본문 부족·LLM 실패가 전체 run을 망가뜨리지 않고 job별 partial result로 남는지 확인한다.
  • operational: body/prompt/raw response가 logs·DB·usage·embedding에 남지 않는지, fixture와 외부 호출 비용을 정리·확인한다.

승인 상태

이전 2026-09-16 승인 범위는 API HUB 검색 계약·메타데이터 후보 발견·기존 본문 정책 유지였다. 사용자는 2026-09-17에 외부 언론사 originallink를 실제 fetch하고 LLM 입력으로 사용하는 확정 설계의 구현을 승인했다.

현재: 설계 승인 · baseline 유지. G1-A의 외부 URL 안전 경계와 G3-A의 본문 기반 content 출력·metadata 기반 category 범위를 유지하며, 실제 구현·검증 결과는 구현 검증 기록에서 관리한다.

확정 baseline: G1-A / G2-A / G3-A / G4-A. public internet을 엄격히 검증하고, 정적 HTML만 추출하며, 기존 구조화 출력과 AGE_GROUP 근거 계약을 재사용하고, 원문은 저장하지 않는다.

결과: design-control self-check는 비차단 이해 확인으로 유지하고, 실제 구현·로컬 게이트·Docker live run 결과는 구현 검증 기록으로 분리했다.

잔여 운영 조건: 정적 HTML로 본문을 얻을 수 없는 JS-only/paywall publisher는 계속 SOURCE_UNAVAILABLE로 처리한다. headless browser나 원문 cache는 별도 설계 없이는 추가하지 않는다.

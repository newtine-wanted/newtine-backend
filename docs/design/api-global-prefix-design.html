목표·범위

모든 일반 HTTP API를 /api 아래에 둔다. 예를 들어 GET /health는 GET /api/health, POST /auth/login은 POST /api/auth/login이 된다.

시스템 모델

구현의 단일 source of truth는 런타임의 app.setGlobalPrefix('api')와 Nestia 입력 분석 설정이다. controller 내부의 도메인 경로는 auth, issues처럼 유지한다.

거부한 대안

  • 각 controller에 api/를 수동으로 반복 입력: prefix가 누락되거나 controller별로 달라질 수 있어 전역 정책보다 취약하다.
  • reverse proxy에서만 rewrite: 애플리케이션의 OpenAPI·SDK·smoke와 실제 public contract가 분리된다.
  • runtime만 변경하고 generated contract 유지: 생성 client가 잘못된 URL을 계속 만든다.

불변 조건

  • 일반 API의 canonical path는 정확히 /api + 기존 controller path다.
  • /health 같은 legacy root path를 계속 지원하지 않는 선택이라면 root 요청은 성공 route로 처리되지 않는다.
  • 응답 body, 인증 정책, 상태 코드, query/body schema, DB side effect는 prefix 변경으로 달라지지 않는다.
  • refresh cookie는 /api/auth, guest feed cookie는 /api/feed scope를 가진다.
  • OpenAPI paths, generated SDK/E2E paths, README·smoke 호출 경로는 동일한 /api 계약을 표현한다.

검증 계획

  1. 생성 계약 재생성 후 OpenAPI의 모든 path와 generated SDK/E2E 호출 경로가 /api로 시작하는지 확인한다.
  2. focused HTTP smoke에서 GET /api/health 200, legacy root 경로의 비성공 상태, 인증·feed·cookie 경계를 확인한다.
  3. npm run format:check, npm run lint, npm run typecheck, npm run test:unit, npm run test:integration, npm run contracts:check, npm run test:smoke를 실행한다.
  4. Compose smoke는 환경이 준비된 경우에만 실행하고, 외부 DB·자격증명 부족은 검증 공백으로 기록한다.
공개 URL 계약 변경이므로 기술 검증 통과만으로 기존 client 호환성이 보장되지는 않는다. G1에서 strict prefix를 선택하면 배포 전 호출자 URL 전환이 운영 전제다.

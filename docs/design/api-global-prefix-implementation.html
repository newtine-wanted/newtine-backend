승인 기준선

API 전역 /api prefix 계약 설계의 2026-09-18 KST 승인 범위를 따른다.

  • G1-A: /api만 canonical public path로 사용하고 legacy root alias는 제공하지 않는다.
  • G2: Nest runtime과 Nestia generated SDK·E2E·OpenAPI paths를 동기화한다.
  • G3: refresh cookie는 /api/auth, guest feed cookie는 /api/feed로 scope를 갱신한다.
  • README·rate-limit·HTTP/Compose smoke·contract expectation을 public path에 맞춘다.

금지 범위: response body·상태 코드·DB schema·도메인 로직·인증 정책·reverse proxy 운영 설정 변경.

현재 구현과 변경 경계

승인된 범위의 as-built 상태다. controller의 상대 경로는 유지하고 public 경계에만 /api를 반영했다.

route prefix 이외의 request validation, response serialization, authorization, persistence 상태 전이는 동일해야 한다.

검증 공백

  • 현재 typecheck·build·contracts:check는 통과했지만, pipeline.validator.ts와 onboarding/generated 정리 변경의 작성자·의도는 이번 prefix 변경과 분리해 확인해야 한다.
  • DB/저장소 준비 전까지 feed·rate-limit·Compose smoke의 완전한 HTTP 검증은 보류한다.
  • 실제 browser cookie path-match는 Node HTTP smoke의 Set-Cookie 확인과 path 경계 검토로 대체되며, 브라우저 실측이 없으면 잔여 위험으로 남긴다.
  • 외부 reverse proxy가 있다면 그 prefix rewrite는 이번 승인 범위가 아니므로 별도 운영 확인이 필요하다.

잔여 위험과 복구

기존 호출자 전환
G1-A로 legacy root는 성공하지 않는다. 배포 전 client base URL을 /api로 전환해야 한다.
생성 계약 누락
contracts:sdk·contracts:e2e·contracts:swagger를 통해 생성해야 post-process가 실행된다. generated path와 OpenAPI path가 모두 /api인지 contract test가 감시한다.
cookie scope 회귀
auth/feed cookie가 새 route에 전송되지 않으면 Set-Cookie Path와 smoke 요청 path를 함께 비교하고 helper·fixture를 같은 변경으로 복구한다.
